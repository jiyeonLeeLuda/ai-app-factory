## 문제

가상 아티스트 "luda"와 팬이 **얼굴 트래킹 영상통화**를 하는 앱. 채팅방(W1 재현) 위에 통화 화면을 얹어, 받는쪽(luda)의 웹캠 → MediaPipe 얼굴 트래킹 → 52→16 표정 매핑 → **DataChannel로 표정 숫자만 전송**, 거는쪽(팬) 기기가 그 숫자로 luda 캐릭터를 렌더한다(B안 — 영상 스트리밍 아님). 거는쪽은 생얼 영상+오디오를, 받는쪽은 오디오만 송출. 통화는 휘발(DB 미저장), 룸 상태는 시그널링 서버 메모리맵으로만. 학습 초점은 **웹 얼굴 트래킹 → 3D 캐릭터 구동 + WebRTC P2P + 내부망 HTTPS**.

## 실패

사람 실기기 확인 전이라 "실패" 확정 항목은 없음. **관찰 대기 항목**(다음 스펙에 넣을 후보 — 조용한 실패 후보):

1. **매핑 방향/스케일 좌우반전** — 단위 테스트는 숫자 크기만 검증, fake device는 expr=0. 실기기에서 "캐릭터가 반대로/과하게 움직임"은 자동으로 절대 못 잡는다. **사람이 실제 얼굴로 봐야만** 드러남 — 자동 초록 로그가 "다 됐다"로 오독될 1순위 지점.
2. **head pose 행렬 규약** — MediaPipe `facialTransformationMatrix`를 column-major(three 규약)로 가정. identity/Y90° 테스트는 통과하나 실제 고개 방향 뒤집힘 가능(미실측 가정).
3. **소리 채널** — 오디오 트랙 add만 확인, 실청취 미검증.
4. lint 우회(queueMicrotask)·head 규약 = 실측 대신 합리적 가정으로 남긴 것 → 실기기 첫 붕괴 후보.

## 배운 것

- **AI**: MediaPipe FaceLandmarker self-host = wasm은 `node_modules/@mediapipe/tasks-vision/wasm/` 복사 + 모델(`face_landmarker.task`)만 Google storage에서 다운로드 → CDN 의존 제거(내부망/오프라인). 52→16 매핑을 순수 함수로 격리해 브라우저 없이 단위 테스트. GPU delegate는 headful 실 GPU에서 WebGL2 정상, blendshape은 xnnpack CPU 폴백해도 무방.
- **FE**: three는 ESM → `useEffect`에서 동적 import, `next/dynamic({ssr:false})`는 client 래퍼 안에서만 → `CallScreenLoader`로 감쌈. rAF 렌더/트래킹 루프는 React state를 거치지 않고 ref로 직접(프레임 방해 방지). 단일 canvas를 role별 CSS로 이동 + ResizeObserver.
- **BE**: https custom server(`https.createServer({cert,key})`)에 ws를 attach → 자동 wss(HTTPS 페이지의 mixed content 차단 회피). 시그널링 룸은 `roomId→sockets` 메모리맵으로만(휘발), 역할 배정=입장 순서. `output:"standalone"` 금지(custom server 미trace).
- **Product**: 캐릭터 전송 B안(DataChannel로 표정 숫자만, 양쪽이 같은 VRM 로드해 렌더) 확정 — 영상 스트리밍(A안) 대비 대역폭·프라이버시 유리하고, 렌더 로직이 W3 클라 렌더 자산으로 그대로 이어진다. 트래킹/렌더/미디어를 얇은 인터페이스(`FaceTracker`/`CharacterRenderer`)로 분리해 W2.9 RN 포팅 대비.
