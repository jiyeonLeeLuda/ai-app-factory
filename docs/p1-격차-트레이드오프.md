# P1 격차 결정 — 트레이드오프 계획서

작성: 2026-09-15. 대상: 1주차 = JYP P1 (AI 페르소나 채팅).
목적: 이번 주 **격차(배울 것) 하나**를 A/B 중 무엇으로 둘지 결정하기 위한 비교. 결정은 내일 이후.

## 고정된 것

- **장면**: 팬이 가상 아티스트에게 말을 걸면, 답이 실시간으로 "타이핑되듯" 흘러나오는 채팅 화면.
- 스택: Next.js App Router + TypeScript + Prisma + Postgres, Vercel 배포 (저장소 규칙 그대로).

## 미결정 — 격차 A vs B

| 축 | A. LLM 토큰 스트리밍 | B. WebSocket 양방향 실시간 |
|---|---|---|
| 배우는 것 | Claude API 스트리밍 → 서버 → 클라 SSE 토큰 릴레이, 페르소나 프롬프트 설계 | 소켓 연결·접속 상태·세션, 양방향 메시지 |
| 1주 배포 현실성 | 높음 — Next.js Route Handler + SSE로 표준 스택에 그대로 얹힘 | 중간 — Vercel 서버리스와 소켓 수명이 안 맞아 별도 인프라/서비스 필요 |
| 장면 정합 | 정확히 겹침 — "말하는 느낌"의 핵심이 토큰 스트리밍 | 부분 — 실시간이지만 "타이핑되듯"의 본질은 아님 |
| 스택 정합 | Vercel/Next에 자연스러움 | 서버리스와 긴장, 마찰 큼 |
| P2(음성)와의 시간축 | 스트리밍 감각을 P2 오디오 스트리밍으로 확장 | 오디오 양방향에서 소켓이 **진짜로** 필요 → 그때 격차로 쓰면 시간축 깔끔 |
| 원샷 난이도 | 낮음 — 앱 로직에 원샷 집중 가능 | 높음 — 인프라 셋업이 원샷을 잡아먹을 위험 |
| 리스크 | 스트리밍 에러/취소 처리 | 서버리스 소켓 수명, 배포 실패 |

## 확정: A (LLM 토큰 스트리밍) — 2026-09-16

근거: (1) 표준 스택에 얹혀 금요일 배포가 현실적, (2) 격차와 장면이 정확히 겹침, (3) WebSocket은 P2 음성 통화에서 진짜로 필요해지므로 그때 격차로 쓰면 "같은 문제를 새 도구로 다시 푼다"는 시간축이 깔끔해짐.

→ 이번 주 격차 = Claude API 스트리밍 → 서버 → 클라 SSE 토큰 릴레이 + 페르소나 프롬프트 설계.

## 확정된 스펙 입력 (내일 스펙 인터뷰 이어서 쓸 것)

인터뷰 1라운드에서 잠긴 것:

- **페르소나**: 하드코딩 1명 (시스템 프롬프트에 고정). 데이터 모델 단순, 장면·격차에 집중.
- **대화 저장**: Postgres에 영속 (Prisma). 스택 명분 충족 + 새로고침해도 대화 남음. 데이터 모델 한 겹 추가.
- **사용자/인증**: 익명 단일 사용자. auth 없음(auth는 원래 W2 격차). 배포 최단.

미결(내일): 격차 A/B 확정 → 그 뒤 데이터 모델·엣지 케이스·검증 명령(S2/S3/S5)·Acceptance Criteria 작성 → 원샷 출발선(스캐폴드 vs 빈 폴더) 결정.
