## 이번 라운드의 핵심 구현 (2부 격차)

- **얼굴 트래킹**: 받는쪽 웹캠 → MediaPipe FaceLandmarker(`outputFaceBlendshapes`+`outputFacialTransformationMatrixes`, VIDEO, numFaces 1) → 매 프레임 `detectForVideo`. 얼굴 유실 시 neutral 복귀(크래시 없음).
- **표정 매핑(격차 코어, 자작)**: `jawOpen→aa`, `(eyeBlinkL+R)/2→blink`, `(mouthSmileL+R)/2→happy`, `browInnerUp→surprised`. head pose = 4×4 행렬 → YXZ 오일러 → `head` 본 회전. 순수 함수라 단위 테스트로 자동 검증.
- **캐릭터 전송 = B안**: 받는쪽이 DataChannel로 `{expr, head}` 경량 JSON을 rAF마다 송출(React state 우회), 거는쪽이 수신 숫자로 luda 렌더. 받는쪽 오디오·거는쪽 생얼 영상+오디오는 평범한 미디어 트랙.
- **시그널링**: 첫 입장=caller(생얼)/둘째=callee(캐릭터), 둘째 입장 시 caller가 offer 생성, 셋째=room-full. 룸은 서버 메모리맵(휘발).
- **HTTPS/wss**: 내부망 IP는 HTTP면 카메라 불가(secure context) → https 서버 필수, ws는 wss.
- **엣지**: 권한 거부/secure context 미충족 안내, 상대 이탈·room-full·neutral 폴백, 모바일 카메라 전환, 언로드 정리.

## 내가 스스로 정한 가정

1. **head pose 행렬을 column-major(three 규약)로 해석** — MediaPipe 문서 대신 three Euler 'YXZ' 추출 규약 채택. identity/Y90° 테스트만 통과 → 실기기에서 방향 뒤집힘 가능(첫 실측 확인 대상).
2. **lint `set-state-in-effect` 우회** — secure-context 판정을 lazy `useState`(`initialBoot`)로 옮기고 init은 `queueMicrotask`로 미룸. 동작 동일, 규칙 준수.
3. **ICE 후보 버퍼링** — remoteDescription 전 도착 후보를 큐에 쌓았다가 flush(loopback 후보 유실 방지). 셀프콜에서 실증.
4. **단일 VRM 캔버스 + role별 CSS 위치 + ResizeObserver** — caller/callee 레이아웃 차이를 canvas 하나로 흡수(ref 충돌 회피).
5. **DataChannel은 caller가 생성**(offerer), 표정은 callee→caller 단방향 전송. 오디오는 양방향, callee는 비디오 트랙 미전송(B안).
6. **fake device 셀프콜은 파이프라인 생존까지만** — 얼굴이 없어 expr=0. 실표정 품질은 사람 Acceptance로 위임(자동화 불가).

## 남은 리스크·미확인

- **표정 매핑 방향/스케일·head 규약** — 자동으로 못 잡는 조용한 실패 1순위. fake device 초록 로그가 "표정 반영 정확"을 뜻하지 않음(전부 neutral). 실기기 육안이 유일한 관측 수단.
- **소리 채널** — add만 확인, 실청취 미검증.
- **내부망 HTTPS 실기기** — cert SAN·서버 기동은 확인, 폰↔노트북 실통화는 사람 몫(폰 rootCA 신뢰 설치 필요).
- **셀프콜 게이트는 headful 필수** — headless는 rAF 정지로 트래킹/렌더 루프가 멈춤(앱 아닌 하네스 제약, 메모리 승격).
