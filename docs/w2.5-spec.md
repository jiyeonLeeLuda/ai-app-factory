## S0. 장면 (필수)

팬이 채팅방에서 **영상통화 버튼**을 눌러 **방번호**를 입력하면, 같은 방번호로 들어온 아티스트(**luda**)와 **양방향 영상통화**가 열린다. 팬은 생얼로 보이고, **luda 쪽은 자기 웹캠 표정을 실시간으로 따라 하는 3D 캐릭터**로 보인다. 팬의 큰 화면엔 표정을 짓는 luda 캐릭터가, 우측 상단 작은 화면(PIP)엔 자기 생얼이 뜬다.

## S0. 격차 (필수)

**웹캠 얼굴 트래킹 → 3D VRM 캐릭터 실시간 구동**, 그리고 그 구동값을 **WebRTC로 P2P 전송**해 상대 화면에서 렌더.
경로: 웹캠 → **MediaPipe FaceLandmarker**(52 blendshape + head pose 4×4) → **VRM 1.0 expression 16종 매핑 룰(자작)** → `@pixiv/three-vrm`로 렌더. 캐릭터 전송 = **B안(DataChannel로 표정 숫자만 보내고 수신측이 직접 렌더)** — 영상 스트리밍(A안) 아님. WebRTC 시그널링은 **W2 custom Node ws 서버 패턴 차용**.

## S1. 사용자 경험 서술

W1 흐름(가입/리스트/채팅방/스트리밍)은 **1부에서 그대로 산다**(p1-spec.md S1). 2부가 더하는 것만 서술한다.

1. **통화 진입**: 채팅방(luda와의 방) 우상단 **영상통화 버튼** → 방번호 입력 → 통화 화면으로 이동.
2. **방 입장·역할 배정**: 같은 방번호로 **첫 번째 입장자 = 거는쪽(생얼)**, **두 번째 입장자 = 받는쪽(캐릭터 luda)**. 두 번째가 들어오면 자동으로 연결(offer/answer) 시작. **3번째 입장 = "방이 찼습니다" 거부**(2인 고정). 별도 방생성 UI 없음(입장=생성 통합).
3. **연결**: 연결되면 **큰 화면 = 상대**, **우측 상단 PIP = 자기 자신**. 통화 상태(연결중/통화중) 표시.
  - 거는쪽(팬) 화면: 큰 화면 = **luda 캐릭터**(받은 표정 숫자로 내 기기가 렌더), PIP = 내 생얼(로컬 웹캠).
  - 받는쪽(luda) 화면: 큰 화면 = **팬 생얼**(받은 영상), PIP = 내 캐릭터(로컬 렌더로 내가 어떻게 보이는지 확인).
4. **얼굴 트래킹(받는쪽)**: 받는쪽이 웹캠 앞에서 표정·고개를 움직이면 캐릭터가 **입 벌림·눈 깜빡·미소·고개 회전**을 따라 한다. POC 수준("적당히 따라 함")이 목표 — 정밀 표정 52종·스무딩은 이번 범위 아님.
5. **소리**: 양쪽 마이크 오디오가 P2P로 오가 **목소리가 들린다**(영상통화다움). STT/TTS·AI 개입 없음 — 원본 음성 그대로.
6. **카메라 전환(모바일만)**: 접속 기기가 모바일이면 **전/후면 카메라 전환 버튼** 노출(데스크톱은 숨김). ※ 받는쪽이 후면으로 전환하면 얼굴이 안 잡혀 트래킹이 멈춤(S3).
7. **통화 종료**: "끊기"로 연결을 닫고 채팅방으로 돌아간다. **통화 내용·영상·트래킹값은 저장되지 않는다**(휘발). 새로고침·이탈 시에도 종료.

## S2. 데이터 모델

**W2.5는 새 테이블을 추가하지 않는다.** W1 스키마(User/Artist/Conversation/Message)는 1부에서 그대로 생기고(p1-spec.md S2), 2부는 그 위에 얹힌다.

- **아티스트 = luda(여성 페르소나)**: W1 seed의 아티스트를 **luda**로 둔다(`Artist.systemPrompt`에 luda 페르소나, `Artist.name = "luda"`). W1이 "필립"이었다면 seed를 luda row 추가. 영상통화는 이 아티스트 방에서만 지원한다.
- **통화·시그널링은 휘발 — DB 미저장.** 영상 프레임·트래킹 blendshape·룸 상태·턴 히스토리 무엇도 저장하지 않는다. **룸 상태(누가 몇 번째로 들어왔나)는 시그널링 서버의 메모리 맵으로만** 유지(`roomId → [socket...]`), 연결이 끊기면 소멸.
- **auth 미룸**: W1과 동일 쿠키 세션(`userId`)만. 영상통화는 로그인 없이 채팅방에서 바로 건다. (진짜 auth는 W4 직전 슬롯)
- **VRM은 에셋(정적 파일)**: DB 아님. `public/models/luda.vrm`로 서빙, 양쪽 클라이언트가 로드.

## S3. 엣지 케이스

W1 엣지는 1부가 커버(p1-spec.md S3). 2부 영상통화 엣지만:

- **방이 꽉 참(3번째 입장)**: "방이 찼습니다" 안내 후 입장 거부. 통화 시작 안 함.
- **혼자 있는 방(상대 미입장)**: 첫 입장자는 "상대를 기다리는 중" 상태로 대기(연결 시도 안 함). 상대가 들어오면 연결 시작.
- **얼굴 트래킹 유실**: 웹캠에 얼굴이 안 잡히면(프레임 아웃·어두움·후면 전환) FaceLandmarker가 빈 결과 → **마지막 표정을 유지하거나 neutral로 복귀**, 크래시 없이 지속. 얼굴이 돌아오면 다시 추적.
- **카메라 전환 시 트래킹**: 받는쪽이 후면 카메라로 전환하면 트래킹 소스가 사라짐 → 캐릭터는 neutral/마지막 표정으로 멈춤(정상 동작으로 간주, 에러 아님).
- **mic/카메라 권한 거부**: `getUserMedia` 거부/실패 시 명확한 안내 + 재요청 버튼, 통화 시작 안 함(빈 통화 진입 금지).
- **secure context 미충족**: `window.isSecureContext`가 false(내부망 IP인데 HTTP)면 카메라 접근 불가 → "HTTPS로 접속해야 카메라를 쓸 수 있습니다" 안내(팬텀 준비물 방지).
- **상대 이탈/네트워크 끊김**: WebRTC 연결(`connectionState`)이 끊기면 "연결이 끊겼습니다" 표시 + 종료. DataChannel·트랙 정리.
- **통화 중 새로고침·언로드**: 페이지 언로드 시 PeerConnection·ws 닫고 시그널링 서버 룸 메모리에서 제거. 재진입은 새 통화.
- **DataChannel 도착 전 렌더**: 거는쪽이 아직 표정 숫자를 못 받았으면 캐릭터를 **neutral 기본 포즈**로 렌더(빈 화면 금지). VRM 로드 완료 전엔 로딩 표시.
- **웹캠 1개 공유(로컬 자동검증)**: 노트북 탭 2개가 같은 물리 웹캠을 동시에 잡으면 충돌 가능 → 자동검증은 **거는쪽을 크롬 fake device(`--use-fake-device-for-media-stream`)** 로 돌려 카메라 1개로 닫는다(S5). 실기기 통화(노트북+폰)는 카메라가 분리돼 문제 없음.

## S4. 비기능 제약

- **스택 고정**: Next.js App Router + TypeScript + Prisma + Postgres, Node 런타임. **pgvector 불필요**. 배포는 로컬 PoC(+ 내부망 HTTPS 실측).
- **전송 = WebRTC (P2P), 시그널링 = WebSocket**: 미디어 서버·SFU **없음**(순수 P2P). 시그널링은 **custom Node server(http**s** + `ws`)** — W2 패턴 차용, offer/answer(SDP)·ICE candidate·방 입장/역할 배정 메시지를 JSON으로 릴레이. Next App Router는 ws를 못 여므로 custom `server.ts` 필수.
  - **STUN**: `stun:stun.l.google.com:19302` 안전망으로 추가(같은 LAN이면 host candidate로 붙지만 무해). **TURN·미디어서버 = Out of Scope**(1:1 로컬/LAN P2P라 불필요).
- **캐릭터 전송 = B안 (DataChannel + 양측 렌더)** — 확정 근거는 설계 회고 참조. 방향별 전송물:
  - **거는쪽(팬) → 받는쪽**: 웹캠 **생얼 영상 트랙** + 마이크 **오디오 트랙** (평범한 미디어 트랙).
  - **받는쪽(luda) → 거는쪽**: **DataChannel로 표정 숫자**(blendshape/head) + 마이크 **오디오 트랙**. **비디오 트랙 없음**(captureStream 안 씀).
  - **양쪽 다 `public/models/luda.vrm` 로드** → 받는쪽은 자기 PIP에 로컬 렌더, 거는쪽은 큰 화면에 수신 숫자로 렌더. **렌더 로직은 공유 모듈**(양쪽 재사용 = W3 클라 렌더 자산).
  - DataChannel 페이로드 = `requestAnimationFrame` 루프마다 `{ expr: {aa, blink, happy, ...}, head: {yaw, pitch, roll} }` 경량 JSON. React state 거치지 말 것(프레임 방해).
- **얼굴 트래킹 = MediaPipe FaceLandmarker** (`@mediapipe/tasks-vision`):
  - `outputFaceBlendshapes: true` + `outputFacialTransformationMatrixes: true`, `runningMode: 'VIDEO'`, `numFaces: 1`, `delegate: 'GPU'`, 매 프레임 `detectForVideo(video, ts)`.
  - **모델(`face_landmarker.task`) + wasm은 `public/`에 self-host**(CDN 의존 제거 → 내부망·오프라인·속도 안전). 원샷이 에셋을 받아 `public/mediapipe/`에 둔다.
- **표정 매핑 룰 (자작 — 격차 코어, Kalidokit 폐기라 참고 구현 없음)**: MediaPipe 52 → VRM 16 **핵심 최소셋만**:
  - `(eyeBlinkLeft+eyeBlinkRight)/2 → blink`, `jawOpen → aa`, `(mouthSmileLeft+mouthSmileRight)/2 → happy`. (+ 여유 되면 `browInnerUp → surprised` 등 소수 추가.)
  - **head pose**: `facialTransformationMatrixes[0]` 4×4 → 회전 추출 → `vrm.humanoid.getNormalizedBoneNode('head')` 회전 적용.
  - `vrm.expressionManager.setValue(name, v)` + `vrm.update(delta)`. **POC라 스무딩(lerp)·스케일 보정·좌우 캘리브레이션은 원샷 이후**(first-pass는 "임계값 반영"까지).
- **VRM 렌더 = three.js + `@pixiv/three-vrm`**: `GLTFLoader.register(p => new VRMLoaderPlugin(p))` → `gltf.userData.vrm` → `scene.add(vrm.scene)` → 렌더 루프 `vrm.update(delta)`. VRoid VRM1 export라 `VRMUtils.rotateVRM0` 불필요.
- **오디오**: 목적은 "소리 채널 생존" 확인까지. `getUserMedia({video, audio:true})`의 오디오 트랙을 PeerConnection에 add. 에코 제거·믹싱 튜닝 없음.
- **Next.js/three-vrm 함정 (조사 확정)**: 렌더 컴포넌트는 `next/dynamic`의 `{ ssr:false }` + 파일 상단 `'use client'` + `useEffect`에서 초기화(canvas ref 타이밍). 안 지키면 SSR에서 `window` 접근 크래시.
  - **번들링(조사 확정 2026-09-17)**: three는 ESM → `useEffect` 안에서 `import`(`require` 금지, `ERR_REQUIRE_ESM`). 로더 경로 = **`three/addons/loaders/GLTFLoader.js`**(three 0.152+ package.json exports 등록, Next 16 기본 Turbopack·webpack 모두 유효). `transpilePackages:['three']`는 **필수 아님**(Turbopack이 `three/addons/` resolve 실패 시에만 추가). react 충돌 없음 — three/three-vrm/tasks-vision 모두 react 무의존(`@react-three/fiber` 미사용이라 next 16.3.5의 react 18/19 어느 쪽과도 무관).
- **HTTPS custom server**: `server.ts`가 `https.createServer({cert,key}, ...)` — cert 경로는 env(`HTTPS_CERT_PATH`/`HTTPS_KEY_PATH`, 기본 `factory/certs/172.10.102.176+3.pem`). **ws는 같은 https 서버에 attach → 자동 `wss`**(HTTPS 페이지에서 `ws://`는 mixed content 차단). `dev: "tsx watch server.ts"` / `start: "NODE_ENV=production tsx server.ts"`, `output:"standalone"` 금지(W2와 동일 제약).
- **의존성 핀**: `next@16.3.5`(w01 실측 성공 버전), `prisma@6`·`@prisma/client@6`, `ws`, `tsx`(W2와 동일). 신규(버전 조사 확정 2026-09-17): **`three@0.180.0`**(three-vrm이 devDep에서 실측한 버전 — `latest` 0.186은 peer `>=0.137`은 통과하나 three-vrm 미검증이라 회피), **`@pixiv/three-vrm@3.5.5`**, **`@mediapipe/tasks-vision@1.0.1`**(독립 패키지, three·react 무관), **`@types/three@0.180.0`**. **`^` 없이 정확 고정** — 자동 마이너 업데이트로 three-vrm 미검증 three 조합이 유입되는 것 방지. `**latest`/RC/canary 금지**, 신규 패키지도 메이저 고정 후 lock.
- **미디어/트래킹 계층 분리 (RN 포팅 대비, W2 선례 계승 — 단 과하지 않게)**: 브라우저 종속 API(`getUserMedia`·MediaPipe·three.js canvas)를 **시그널링·통화 로직과 얇은 인터페이스로 분리**. 예: `FaceTracker { start(video); onFrame(cb) }`, `CharacterRenderer { load(url); apply(expr, head) }`. 통화/시그널링 로직은 인터페이스만 의존 → W2.9 RN 포팅 때 어댑터만 교체. **과분리 금지**(격차가 트래킹 자체라 경계만 긋고 추상화는 최소).
- **실행 환경**: 자동검증 = 노트북 `localhost`(secure context 예외). 실측 = 노트북 서버 + 핸드폰이 **내부망 HTTPS**(`https://172.10.102.176:3000`)로 접속. 시크릿(cert key)은 서버에서만.

## S6. 원샷 실행 규칙 (2부 부트스트랩)

**폴더 구조 (2부 완성형)** — 단일 Next 앱을 custom Node **https** server로 감싼다. `server.ts`가 문지기: HTTPS 요청은 Next로, `/ws` 업그레이드는 시그널링 핸들러로.

```
apps/w025-face-track-call/
  server.ts              # custom https 시동 = 문지기 (https.createServer + cert)
                         #   - 일반 요청 → Next handler
                         #   - 'upgrade'(/ws) → 시그널링 핸들러(wss)
  app/
    (chat)/…             # 1부: W1 채팅 화면 그대로 (p1-spec.md S1)
    call/[room]/         # 2부: 통화 화면 (클라: 웹캠·트래킹·WebRTC·렌더)
  lib/
    signaling/           # ws 업그레이드·룸 관리(roomId→sockets)·역할 배정·offer/answer/ICE 릴레이
    rtc/                 # RTCPeerConnection 셋업·트랙/DataChannel 관리 (통화 로직)
    tracking/            # FaceTracker 인터페이스 + MediaPipe 웹 어댑터 (52→16 매핑 룰)
    render/              # CharacterRenderer 인터페이스 + three-vrm 어댑터 (양쪽 공유)
    …                    # W1 lib (prisma, openai client 등) 재사용
  public/
    models/luda.vrm      # 사람 준비물(factory/luda.vrm)에서 복사
    mediapipe/           # face_landmarker.task + wasm (self-host)
  prisma/                # 1부 스키마·seed(luda) 그대로 (새 테이블 없음)
  package.json           # dev/start가 반드시 server.ts를 타게
```

**0. 프리체크**: `CREATE_DB_URL`로 Postgres + `factory` role 확인(실패 시 멈추고 안내, 슈퍼유저 자가승격 금지). **추가**: `factory/luda.vrm`·`factory/certs/*.pem` 존재 확인 — 없으면 멈추고 사람에게 안내(팬텀 준비물 방지).

**1. 폴더 리셋**: 대상 = `apps/w025-face-track-call/`만(상위·타 앱 금지). 있으면 삭제 후 재생성.

**2. 1부 — W1 재현(얇게)**: `docs/p1-spec.md` 개정본(함정 5개 예방)의 S6·S2~S4를 이 폴더에서 수행. 슬러그 `w025-face-track-call` → DB `w025_face_track_call`. seed 아티스트 = **luda**. **채팅 스트리밍까지 재현하되** 여기서 p1-spec.md S5 검증을 먼저 통과(1부 깨지면 2부 진입 금지). 상속 함정 5개(next 핀·reasoning.effort·.env 따옴표·프리체크 실행·dev 포트 정리) 확인.

**3. 2부 — 영상통화 얹기**:

- **https custom server**로 전환(cert 로드, ws→wss attach, `/ws` 시그널링 라우팅).
- **에셋 배치**: `factory/luda.vrm` → `public/models/luda.vrm`. MediaPipe 모델·wasm → `public/mediapipe/`.
- **통화 진입**: 채팅방에 영상통화 버튼 → 방번호 입력 → `call/[room]` 라우트.
- **시그널링**: 룸 입장(첫=caller/생얼, 둘째=callee/캐릭터, 셋째 거부), offer/answer/ICE 릴레이.
- **거는쪽**: 웹캠 영상+오디오 송출 / 받는쪽 표정숫자 수신 → luda 렌더(큰 화면).
- **받는쪽**: 웹캠→MediaPipe 트래킹→52→16 매핑→DataChannel 송출 + 로컬 렌더(PIP) / 마이크 오디오 송출 / 팬 생얼 수신(큰 화면).
- **모바일 카메라 전환** 버튼(모바일 감지 시).

**4. 검증**: S5 실행.

⚠️ **원샷 함정 (조사·설계에서)**:

- **secure context**: 카메라는 HTTPS(또는 localhost)에서만. 내부망 IP는 HTTP면 `navigator.mediaDevices`가 undefined. → https server 필수, ws는 wss(mixed content).
- **표정 매핑 방향/스케일**: 52→16 자작 매핑이 좌우반전·스케일 어긋날 수 있음. first-pass는 "임계값 반영"까지만, 스무딩·보정은 이후.
- **DataChannel vs 미디어 트랙 혼동**: 받는쪽 캐릭터는 **비디오 트랙이 아니라 DataChannel 숫자**로 감. 거는쪽이 렌더. (A안 captureStream 아님.)
- **양쪽 VRM 로드**: 거는쪽도 luda.vrm 로드해야 렌더 가능. 로드 전 neutral 폴백.
- **웹캠 1개 자동검증**: fake device 플래그로 거는쪽 대체(S5).
- **MediaPipe self-host**: CDN 의존 시 내부망/오프라인 실패 → `public/`에 번들.
- **three.js SSR 크래시**: `dynamic({ssr:false})` + `'use client'` + `useEffect` 초기화.

## S5. 검증 명령

AI가 one-shot 안에서 스스로 실행해 통과를 확인한다.

- **(1부)** p1-spec.md S5 전부: `typecheck`/`lint`/`build`/`prisma validate`/`migrate dev`/`db seed`(luda) 통과.
- **(2부)** `npm run typecheck`/`npm run lint`/`npm run build` — 2부 코드 포함 통과.
- **https custom server 기동**: `npm run dev`로 서버가 뜨고 `https://localhost:3000` 응답 + `/ws` 업그레이드(wss) 응답.
- **매핑 룰 단위 테스트**: 샘플 blendshape 입력 → 매핑 함수 출력이 기대 VRM expression 값인지(예: `jawOpen:0.8` → `aa≈0.8`, 얼굴 유실(빈 입력) → neutral). 순수 함수라 자동화 가능.
- **셀프콜 자동 게이트(개입 0)**: 노트북 탭 2개(거는쪽 = fake device)로 같은 방번호 입장 → **P2P 연결 성립(`connectionState==='connected'`) + DataChannel open + 거는쪽이 수신 숫자로 렌더 루프 진입 + 트래킹값이 `expressionManager`에 반영되는 콘솔 로그**. (실제 표정 품질·실기기·자연스러움은 자동화 불가 → 사람 Acceptance.)

## Acceptance Criteria (필수)

완료 선언 직후 사람이 체크한다. **1부(재현)와 2부(격차)를 분리 채점**(1부 = 회귀 게이트 통과/실패 이진, `metrics.csv`의 `w025` 행은 2부 기준). 1부가 깨지면 원샷 중단·기록하되 W2.5 격차 점수엔 반영 안 함.

**1부 — W1 재현 (회귀):**

- [ ] `apps/w025-face-track-call/`에서 W1 채팅 앱이 그대로 뜬다(가입·리스트·채팅 스트리밍, 아티스트 luda). p1-spec.md Acceptance 통과.

**2부 — 얼굴 트래킹 영상통화 (이번 격차):**

- [ ] 채팅방 영상통화 버튼 → 방번호 입력 → 통화 화면 진입.
- [ ] 같은 방번호로 둘째가 입장하면 자동으로 P2P 연결된다(첫=생얼, 둘째=캐릭터).
- [ ] 3번째 입장은 "방이 찼습니다"로 거부된다.
- [ ] 연결되면 **큰 화면=상대, PIP=자기**가 양쪽 모두 보인다(영상통화 레이아웃).
- [ ] 거는쪽 큰 화면에 **luda 캐릭터가 보이고**(거는쪽 기기가 수신 숫자로 렌더), 받는쪽 큰 화면엔 팬 생얼이 보인다.
- [ ] (실측·격차 핵심) 받는쪽이 **입을 벌리면 캐릭터 입이 벌어지고(aa), 눈을 감으면 깜빡이고(blink), 웃으면 미소(happy), 고개를 돌리면 캐릭터 고개가 따라 돈다**(head pose). — 사람이 실기기로 확인.

- [ ] 모바일 접속 시 카메라 전환 버튼이 뜨고(데스크톱은 없음), 후면 전환 시 크래시 없이 트래킹이 멈춘다.
- [ ] 얼굴이 프레임을 벗어나도 크래시 없이 neutral/마지막 표정으로 유지되고, 돌아오면 다시 추적한다.
- [ ] 카메라/mic 권한 거부 시 명확한 안내가 뜨고 빈 통화로 진입하지 않는다.

- [ ] **(실측·내부망 HTTPS)** mkcert cert 적용 후 **핸드폰이 `https://172.10.102.176:3000`로 접속**해 노트북↔폰 실기기 통화가 성립한다(카메라 열림 = secure context 충족, 연결·트래킹·소리 확인).
