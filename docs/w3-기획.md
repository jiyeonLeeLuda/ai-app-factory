# W3 1단계 기획 — AI 아바타 음성통화 (격차 확정 + 설계 판단 + grilling)

작성 2026-09-17 (오토모드). 재료: `docs/w3-0단계-점수표.md`(감산)·`docs/w3-선행조사.md`(증거)·씨앗. 이 문서 = 스펙 쓰기 직전의 **확정된 기획**. grilling 압박검증까지 통과한 상태.

---

## 1. 격차 (감산 결론 재확인)

> **이미 만든 VRM 렌더러(W2.5)를, 웹캠이 아니라 AI 출력으로 구동한다: TTS 오디오 진폭 → 입(`aa`) + LLM emotion → 표정.**

first-pass 임계값: 립싱크(목소리에 입이 움직인다·필수) + emotion 표정(라벨에 표정이 눈에 띄게 바뀐다·1:1 map·~0.3s lerp). 정밀 비짐/감정강도/문장별emotion/보정 = 스트레치·Out.

## 2. 핵심 설계 판단 (feedback-share-deliberation 형식 — 지연 검토용)

지연 부재라 내가 정했으나, 두 갈래 이상 고민한 것은 ①고민 ②선택지 장단 ③기운 쪽+확신도로 남긴다. 집에서 뒤집을 수 있게.

### 판단 A — emotion 획득: strict JSON vs **구분자 프로토콜** ★

- **고민:** 씨앗은 `LLM(JSON {text,emotion})`이라 적음. 그대로 가면?
- **선택지:** (JSON) 규격 깔끔·타입 안전 / **BUT 스트리밍 시 필드단위로 안 옴 → 통짜 대기 → W2 첫문장 지연트릭 붕괴**(선행조사 §1). vs (구분자 `[[emotion]]` 선두 태그) 스트리밍 보존·구현 단순 / BUT 모델 준수 의존.
- **기운 쪽: 구분자 프로토콜.** 폴백(무효 시 neutral)으로 준수 리스크 방어. **확신 높음** — 지연 지속 tenet "일반론<실측"과 P1 `role` 교훈("API 모르고 스펙 쓰면 갈아엎음")의 직접 적용.

### 판단 B — emotion 세분도: 문장별 vs **1응답=1**

- **고민:** 응답 도중 감정이 바뀌면(웃다가 슬퍼짐) 선두 1태그는 뒤를 못 맞춤.
- **기운 쪽: 1응답=1 emotion(first-pass).** 문장별 emotion = 스트레치. **확신 높음** — POC 임계값(W2.5 "임계값까지"와 동형), 격차 하나 규율.

### 판단 C — 팬 자기 화면: 웹캠 PIP vs **없음(mic 인디케이터)** 

- **고민:** "영상통화 UI"인데 팬은 카메라가 없다(트래킹 안 함). 자기 모습 PIP를 넣나?
- **선택지:** (웹캠 PIP) 통화 UI 관습 충족 / BUT `getUserMedia(video)` 재도입 = 이번 격차(AI 구동) 오염·복잡도↑. vs (없음) 화면을 luda 아바타가 지배, 팬은 **mic 활동 인디케이터**로 "들리고 있음"만 표시.
- **기운 쪽: 없음 + mic 인디케이터.** AI 아이돌과의 통화는 "상대를 본다"가 핵심이지 자기를 볼 필요 없음. 웹캠은 W2.5 격차였지 W3 격차 아님. **확신 중상** — 자기화면 부재가 허전할 수 있으나 격차 순수성이 우선. (지연이 원하면 스트레치로 웹캠 PIP 복원 가능.)

### 판단 D — 프레이밍: **얼굴 클로즈업 재사용** / 판단 E — 서버: **W2 custom ws 재사용**

- D: W2.5 `CAM_DIST≈0.55` 얼굴 클로즈업 그대로. 신체 트래킹 없으니 상반신 프레이밍 이점 없음. 확신 높음.
- E: W2 custom https+ws(오디오 릴레이) 재사용. CF/Vercel = 측정런에 인프라 리스크. 확신 높음(0단계 채점 근거).

## 3. grilling 압박검증 (자가 — 지연 위임)

지연 부재라 공격·방어를 다 잡아 계획을 반박하고, 노출된 약점을 스펙에 반영했다. 진짜로 파인 것만 기록.

**G1 — 구분자 파서가 발화 중간 `[[…]]`에 오작동?** 
모델이 `[[happy]] 안녕! 오늘 [[진짜]] 좋아`처럼 중간에 대괄호를 또 뱉으면? → **파서는 선두 태그 1개만 떼고**(첫 ~24자), 이후 `[[…]]`는 발화 텍스트로 남아 TTS가 그대로 읽는 사고 가능. **반영:** ①instructions에 "태그는 맨 앞 한 번만" 명시, ②문장→TTS 직전 **stray `[[...]]` 정규식 제거**(sanitize), ③무효/누락 시 neutral 폴백. → 스펙 S3·S4.

**G2 — emotion 라벨이 enum 밖(`[[excited]]`)?** → 파싱값이 집합에 없으면 **neutral**. 스펙 S3.

**G3 — 1인 사용인데 W2.5 P2P를 실수로 끌고 오나?** 진짜 위험. W3는 **브라우저↔서버 ws(오디오 릴레이)** 만 필요 — **PeerConnection·signaling·room·role 전부 불필요.** **반영:** 스펙이 W2.5의 `lib/rtc`·`lib/signaling` 재사용을 **명시적으로 금지**하고 W2의 `lib/voice`·`lib/audio` 재사용을 지정. (W2.5보다 단순해지는 게 핵심 — 오버스펙 방어.)

**G4 — 첫 턴 자동재생 + AudioContext 잠김?** luda 선턴("여보세요")은 제스처 없이는 못 울림. **반영:** "통화 시작" 클릭 한 제스처에서 ①무음`<audio>` unlock(W2) ②`audioContext.resume()`(선행조사 §2-4) 둘 다. 선턴은 클릭 후 재생. 스펙 S1·S4.

**G5 — 립싱크 CORS 무음/이중소스 throw?** 선행조사 §2 함정 3종(same-origin·destination connect·createMediaElementSource 1회). **반영:** 스펙 S4에 못박음 + S5 검증에 aa 매핑 단위테스트.

**G6 — 사람 없이 파이프라인 자가검증?** W2.5는 P2P 셀프콜 게이트였으나 W3는 P2P 없음. **반영:** W2식 **파이프라인 통합테스트**(샘플 발화 오디오→STT 비어있지않음→LLM 텍스트+emotion 파싱→문장분할→TTS mp3 바이트) + **신규 순수함수 2개 단위테스트**(RMS→`aa`, emotion→expression). 실제 "입 움직임/표정 변화"는 사람 Acceptance(W2.5 실기기 트래킹과 동형). 렌더 rAF는 headless서 멈추므로(W2.5 교훈) 자동검증은 순수함수·파이프라인까지만.

**G7 — 오버스펙 재점검.** 격차 밖 추가된 것? idle blink/breathe = "살아있는 아바타" 장면 최소요소(유지, 화려한 idle은 스트레치). barge-in(팬이 luda 말 자르기) = **Out**(POC 턴제). head 트래킹 = 없음(idle sway만). 팬 웹캠 = 없음. → 격차 하나 유지 확인.

**결과: 통과.** G1·G2·G3·G4가 스펙 문구를 정정(파서 sanitize·enum 폴백·P2P 재사용 금지·2제스처 unlock). 종이 위에서 원샷 헤맬 4곳을 앞단에 잡음 = Y축 수렴 라운드 1건.

## 4. 스펙으로 넘길 확정 요약

- 격차 = AI 출력 구동(립싱크+emotion). 2부 구조(1부 W1회귀+2부 격차), 1인 사용(P2P 제거).
- emotion = 구분자 `[[emotion]]` 선두 태그(strict JSON 폐기)+sanitize+neutral 폴백, 1응답=1.
- 립싱크 = MediaElementSource(1회)→Analyser→destination, time-domain RMS→lerp→aa, same-origin/blob, resume는 시작 제스처.
- UI = 풀스크린 luda 얼굴 클로즈업(재사용), 팬 웹캠 없음+mic 인디케이터, 통화컨트롤(음소거·끊기).
- 서버 = W2 custom https+ws 오디오 릴레이 재사용(W2.5 rtc/signaling 재사용 금지).
- 검증 = W2식 파이프라인 통합 + 신규 순수함수 2개 단위 + 사람 Acceptance(입·표정).
