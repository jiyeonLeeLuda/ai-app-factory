# Run 2 측정 로그 기록 — 킥오프 지시문

> 사용법: **새 세션**을 저장소 루트에서 열고 "이 파일을 읽고 실행해줘"라고 한 뒤 이 파일을 투입한다.
> 이 작업은 코드 생성이 아니라 **원샷 재실행(run 2) 결과를 측정 기준에 맞춰 기록**하는 것이다.

## 배경 (최소)

- 이 저장소는 "AI 앱 팩토리": 승인된 스펙 하나로 앱을 **원샷 생성**하고, 완료 후 **개입 횟수·first-pass**를 측정한다.
- 대상 = **P1 AI 페르소나 채팅**. 앱 폴더 `apps/w01-persona-chat/`, 스펙 `docs/p1-spec.md`.
- **run 1**은 토큰 스트리밍으로 생성됨(자가 보고: `docs/p1-완료보고.md`). 실사용 후 UX를 **문장 단위 다중 말풍선(B안)**으로 바꾸고 스펙을 고쳤다. 그 과정에서 발견한 것도 스펙에 엣지로 반영(Prisma 6 핀, role 프리체크, 2턴째 blank 버그 방지 등).
- **run 2** = 그 **개선된 스펙으로 재생성**한 것. 핵심 관심사: *개선된 스펙이 원샷을 더 잘 굴렸는가(공장 피드백 루프)*.
- **run 1 기록은 이미 `logs/w01.md`·`factory/metrics.csv`에 있다. 덮어쓰지 말고 run 2를 별도로 추가한다.**

## 측정 기준 (기록 전 반드시 읽기)

- `logs/w01.md`의 **"측정 기준"** 절
- `CONTEXT.md` — 용어 정의(intervention 5종: 설계오류/구현버그/스타일/누락/진행넛지, first-pass)
- `docs/p1-spec.md`의 **Acceptance Criteria** + "S1 진화(B)" + S3 엣지
- **판정 원칙**: first-pass는 **원샷 산출물 vs 스펙-원문**으로 판정. 완료 후 사람이 손으로 고친 것은 first-pass 실패가 아니라 개입/진화로 분리. 환경 마찰(role·의존성 등)은 앱 개입이 아니라 별도(gotchas).

## 할 일

1. **재생성 앱 확인**: `apps/w01-persona-chat/` 구조, `package.json`의 **Prisma 버전이 6인지**, 채팅 코드가 **문장 분할(B안)로 구현됐는지**(토큰 단위가 아니라).
2. **자동 검증 실행(증거 남기기)** — `apps/w01-persona-chat/`에서:
   `npm run typecheck` · `npm run lint` · `npm run build` · `npx prisma validate`
   각 통과/실패를 기록.
3. **사람(지연)에게 물을 것** — CLI로 확인 불가한 런타임/맥락:
   - 재실행 중 **개입을 몇 번** 했나? 각각 5종 중 무엇인가? (없으면 0)
   - ⚠️ **2번째·3번째 응답도 정상**인가? (run 1 hand-B의 "2턴째 말풍선 사라짐" 버그가 재발 안 했는지 — 이번 재실행의 핵심 관문)
   - 답이 **여러 말풍선으로 쪼개지나**? (반말·마침표 없어도 줄바꿈으로 분할되나)
   - **"..." 타이핑이 전송 즉시** 뜨나?
   - 가입·다른 사용자 격리·중지 꼬리표·새로고침 복원·필립 톤
   - **spec_prep 시간 / 원샷 소요 시간 / 비용**(대략, 모르면 빈칸)
   - 위 자동4 + 런타임 결과로 **first-pass 최종 판정**(성공/부분/실패)
4. **기록**:
   - `logs/w01.md` 맨 아래에 **`## Run 2 (재실행 — 개선 스펙)`** 섹션 추가. 위 측정 기준 그대로 적용해 Acceptance 항목별 ✅/⏳/❌, 개입 집계, **run 1 대비 개선점**(피드백 루프가 실제로 작동했는지: 2턴째 버그·Prisma·role이 이번엔 매끄러웠나)을 적는다.
   - `factory/metrics.csv`에 **`run_id=w01-p1-r2`** 행 추가. 아는 값만, 모르는 건 빈칸. (run 1 행은 그대로 둔다)
   - **미확인 항목은 "미확인"으로 정직하게.** "빌드 통과"를 "동작함"으로 부풀리지 말 것.
5. **커밋은 사람이 지시할 때만.** 앱 폴더(`apps/`) 변경 커밋은 지연 확인 후.

## 산출물

- `logs/w01.md`에 Run 2 섹션 1개
- `factory/metrics.csv`에 run 2 행 1개
- 마지막에: run 1 대비 **"개선된 스펙이 원샷 품질을 올렸는가"**에 대한 3~4줄 판단(공장 피드백 루프 성패).
