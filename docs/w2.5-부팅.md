## 1. 앱 정의 (라인업 기준 — Step 0에서 재확정)

- **W2.5 = 얼굴 트래킹 영상통화.** 장면: 실시간 **양방향 영상통화**에서 얼굴 표정을 트래킹해 **3D 가면**을 씌운다.
- **전송 = WebRTC** (W2=WebSocket과 겹침 없음 — JD 키워드 분산).
- 격차 후보(엉킨 조각): WebRTC 시그널링 / 양방향 영상 / 얼굴 랜드마크 트래킹 / 3D 렌더 / 가면 합성.

## 2. 절차 (감산형 pre-spec 게이트 — 순서대로)

**Step 0 — 목적·축 tilt·승리조건**
- 목적 한 줄
- 축 tilt (X 기술어필 / Y 팩토리 / Z 빈지식) + **축별 승리조건**. 기본 Y>X>Z 유지하되 이번 주 특이점 반영.

**격차 하나로 감산 (핵심)**
- 위 엉킨 조각을 **3축으로 채점**(vibes 금지)해 격차 **1개**로 좁힌다. 나머지는 Out of Scope / 다음 주.
- ⚠️ W2.5는 조각이 많다(WebRTC+얼굴+3D). 감산이 이번 주 성패 — 욕심내면 원샷 first-pass 붕괴.

**선행조사 (공식문서 근거 — 서브에이전트로)**
- WebRTC(시그널링·STUN/TURN·P2P vs 미디어서버), 얼굴 랜드마크(MediaPipe/face-api 등), 3D 렌더(Three.js 등)
- API 규격·모델명·라이브러리 버전은 **공식문서**에서(기억 금지). **사실은 서브에이전트 조사, 결정은 사용자.**
- 참고: 영상통화 아키텍처는 W2(음성)와 다름 — P2P면 서버 가벼움(시그널링만), AI 개입이면 미디어서버로 무거워짐(회고 참조).

**grilling 게이트**
- pre-spec 초안 → **`/grill-me`로 압박 검증**(원샷 first-pass 리스크·근본 결정). 조사 필요 사실은 서브에이전트, 결정은 사용자.

**SPEC 작성**
- `factory/SPEC_TEMPLATE.md`로 W2.5 SPEC.md. **사람 준비물**·검증 명령·Acceptance 명시.
