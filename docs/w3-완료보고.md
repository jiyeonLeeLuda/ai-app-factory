## 이번 라운드의 핵심 구현 (2부 격차 = "구동 소스 교체")

- **격차 ① 립싱크**: 재생 `<audio>`에 `AnalyserNode` 1회 부착 → rAF마다 `getByteTimeDomainData`→RMS→`aa=clamp(rms*GAIN,0,1)`→lerp 스무딩→`renderer.setMouthOpen`. 정지 시 aa→0(입 다물기). 3함정 방어: `createMediaElementSource` 1회·destination connect 필수·same-origin blob(ws→Blob→objectURL).
- **격차 ② emotion**: LLM 응답 선두 `[[emotion]]`을 스트리밍에서 즉시 파싱→`{type:emotion}` ws 전송→`renderer.setEmotion`(~0.3s lerp). 태그 뗀 텍스트는 W2 문장분할→TTS로 그대로(지연트릭 보존). 무효/누락→neutral, TTS 직전 stray `[[...]]` sanitize.
- **첫 턴 선턴**: 연결 직후 `emotion:relaxed` + "여보세요?" TTS.
- **idle**: 시간기반 blink(2~5s)·미세 호흡 sway(트래킹 불필요).
- **엣지**: STT 빈 결과→듣는 중 복귀, 권한 거부/중단류 구분, secure context 안내, 아바타 로딩 표시, 음소거·끊기·언로드 정리(휘발).

## 원샷 내부에서 자가해결한 gotchas (다음 앱 상속 함정 방지)

1. **eslint FlatCompat → next16 순환 크래시**: W2에서 상속한 `eslint.config.mjs`(`@eslint/eslintrc` FlatCompat)가 next16에서 `Converting circular structure to JSON`으로 lint 통째 사망. → W2.5가 쓰던 **next16 네이티브 flat config**(`eslint-config-next/core-web-vitals`·`/typescript` + `defineConfig`/`globalIgnores`)로 교체.
2. **next16 dev 데몬 stale lock**: 첫 `npm run dev`가 **EADDRINUSE**(포트 3000을 다른 세션 dev 서버가 선점)로 실패하자, next16이 남긴 dev 데몬/락(`.next/dev`)이 "existing server 있음"이라고 안내하면서 실제론 아무것도 안 서빙(curl HTTP 000). → 관련 node 프로세스 전부 kill + `rm -rf .next/dev` 후 단일 클린 기동, `curl`로 실제 200 폴링 확인. (`lsof -nP -i :3000`로 점유 정체 확인이 안전)

**상속 함정 5개 차단 확인**: next16.3.5 핀 / `reasoning.effort:minimal`(빈 응답 방지 — 통합테스트 35자로 검증) / `.env` 따옴표 없이 기록 / 프리체크 실명령 실행(DB role·luda.vrm) / dev 포트 좀비 정리.

## 자동으로 못 잡는 조용한 실패 (실측 1순위)

- **립싱크 GAIN 미스매치** — 입이 거의 안 움직이거나 덜덜거려도 크래시·테스트 통과. rAF가 headless서 멈춰 자동관측 불가.
- **emotion 표정 공백** — `setValue`는 부르지만 luda.vrm이 프리셋을 비워뒀으면 표정이 neutral처럼 미동 없음(값 주입≠표정 표시). 육안이 유일 관측.
- **aa↔emotion 블렌드** — `happy`(미소 입) + `aa`(입 벌림) 동시 setValue 시 립싱크가 먹힐 가능성.

## 내가 스스로 정한 가정

1. **emotion 규약을 `buildCallInstructions`(통화 전용)에만** — 스펙 S2는 "systemPrompt에", S4는 "instructions에"로 갈렸으나, systemPrompt에 넣으면 채팅(1부)이 그대로 써서 채팅 답변에 `[[happy]]`가 샌다. 의도(통화에서만 태그) 우선.
2. **선턴 emotion = `relaxed`** 하드코딩 — 선턴 인사는 LLM 미경유(고정 "여보세요?")라 표정도 고정값.
3. **립싱크 스무딩은 렌더러에서, raw aa는 LipSync에서** — `read()`는 순수 진폭, lerp는 `characterRenderer.drive`가 담당(테스트 가능 경계).
4. **W2 통째 복사 > 빈 폴더 재스캐폴드** — 회귀 게이트 안정성 우선(재현성). 대가로 상속 config 함정 2개를 만나 자가해결.

## 실측 변경 로그 (2026-09-18, 원샷 이후 튜닝)

원샷 산출물을 지연이 실기기로 돌려보며 여러 왕복으로 다듬었다. 스펙 본문 대비 바뀐 결정은 `docs/w3-spec.md`의 **"실측 개정 (v1.1)"** 섹션에 못박음. 여기서는 무엇을·왜 바꿨는지 시간순 요약.

**대화 품질**
- 대화 모델 `gpt-5-nano` → **`gpt-5.6-luna`**(재미·톤). ⚠️ 함정: luna는 `reasoning.effort:'minimal'` 미지원 → 400. `none`으로 교정(파이프라인 테스트가 잡음).
- luda 페르소나 강화(성격·유머·관심사). 파이프라인 테스트 응답이 실제로 되묻고 관심사를 꺼냄("창밖 보며 아이스 아메리카노").

**목소리**
- `gpt-4o-mini-tts`의 `instructions`로 딜리버리 조종("밝고 발랄한 소녀"), 모델·보이스·지시 전부 env. 보이스 nova→shimmer→coral→sage→marin→ballad 순으로 귀 A/B, **marin 잠정 채택**(발랄함은 계속 튜닝 대상).
- 교훈: **보이스 음색·성별을 기억으로 추측·라벨링하지 말 것** — 공식문서에 설명 없음. 지연 지적으로 메모리에 반영. `alloy/ash/echo/fable/onyx/verse/cedar`도 "남성"이라 단정 불가(내 추측이었음).

**아바타 표정·입·눈**
- 표정을 "고정"에서 **"말할 때 유지 → 조용해지면 neutral 복귀"**(순간 이벤트)로. 세기 `EMO_MAX=0.7`.
- 입 `AA_GAIN 4→2.5` + `MOUTH_MAX=0.5`(과개방→오물오물). 눈 깜빡임 사인 곡선·주기 3~6s(급격한 "갑자기 작아짐" 완화).

**인사 손짓 — 수동 각도 → VRMA (핵심 전환)**
- 처음엔 팔뼈 회전 각도를 손으로 맞췄으나 **여러 번 관절 꺾임·손 안 보임**으로 실패. 지연 제안대로 **기성 애니메이션**으로 전환.
- `@pixiv/three-vrm-animation@3.5.5` + `waving.vrma`(AnimationMixer 재생). 자연스러움 확보. 인사 후 어깨·팔·손을 A포즈로 lerp 복귀("만세" 잔상 대응).
- 함정: `.vrma`가 GitHub **LFS**라 raw URL이 131B 포인터만 줌 → `download_url`(media)로 실파일 192KB 확보.
- ⚠️ `waving.vrma`는 **라이선스 없는 커뮤니티 repo의 임시 placeholder** → 배포 전 정식 모션 교체 필요. **git 미커밋(로컬 에셋)**.

**프레이밍**
- 얼굴 클로즈업(0.55) → **상체 위주(1.15, 겨냥 -0.15)** — 손인사가 보이게. 카메라 무빙은 제거(고정).

**미확정(사람 실측 대기)**: 인사 손짓 최종 형태·"만세" 잔상 여부, 상체 프레이밍 정확도, marin 발랄함. 전부 육안 판정 노브로 상수화 — 실측 후 값만 조정하면 됨. 자동검증(typecheck/lint/build/단위/파이프라인)은 매 변경마다 통과 유지.
