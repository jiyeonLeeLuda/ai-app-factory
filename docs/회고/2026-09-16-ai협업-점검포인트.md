# AI 협업 회고 — P1 스펙 설계 세션

날짜: 2026-09-16. 대상: P1(AI 페르소나 채팅) 스펙 데이터 모델 설계 논의.
목적: 나중에 스스로 회고하기 위한 기록. "AI를 쓸 때 무엇을 점검해야 하는가"를 이 세션에서 실제로 겪은 대화로 남긴다.

---

## 이 세션에서 실제로 오간 흐름

1. 격차 A/B(토큰 스트리밍 vs WebSocket) → **A 확정**.
2. 데이터 모델 S2 검토 시작. AI 초안은 `Conversation` + `Message` 2개, 페르소나는 코드 상수.
3. 내가 "여러 아티스트가 늘어날 구조로 이미 바꿨다"고 밝힘 → `Artist` 개념 필요성 논의.
4. "페르소나가 하드코딩/DB에 있으면 매 API 요청마다 프롬프트로 보내는 거냐?" 질문 → LLM 무상태성 확인.
5. 미래 기능(RAG·개인화 메모리·이벤트)은 **이번 주 아님, 메모만**으로 정리.
6. `Artist` 테이블 DB 관리로 승격 결정.
7. 큰 토론: "원샷 앱이니 테이블도 최소화했어야 했나?" → **코드는 싸졌지만 데이터·설계는 안 싸다**는 재구성.
8. 우선순위 확정: **공장 절차 단련 1순위**, JYP는 그다음(이직이 목표라 이전 가능한 자산 우선).
9. 규율 확정: **고치기 전에 측정한다**, 측정 데이터는 회차별로 별도 누적.

## AI를 쓸 때 점검할 부분 (이 세션에서 건진 것)

### 1. AI의 첫 설계는 "합리적 기본값"이지 내 맥락이 아니다
AI는 `Conversation`+`Message`만 제시했다. 틀린 게 아니라 **단일 아티스트를 가정한 기본값**이었다.
내가 "여러 아티스트로 갈 거다"라는 맥락을 주자 설계가 바뀌었다.
→ **점검**: AI 초안을 받으면 "이건 무슨 가정 위에 서 있나?"를 먼저 묻는다. 내 맥락을 안 주면 AI는 가장 무난한 가정을 택한다.

### 2. "왜 이게 여기 있나"를 끝까지 캐물으면 설계가 단단해진다
`Conversation`이 왜 필요한지 물었을 때, "단일 스레드면 사실 군더더기"라는 정직한 답이 나왔고,
거기서 "그럼 미래 개인화 메모리는 어디 사나 → 관계(대화방) 단위"라는 진짜 설계 근거가 드러났다.
→ **점검**: AI가 "필요하다"고 하면 "없으면 뭐가 안 되나"를 되묻는다. 정당화가 약하면 구조가 약한 것.

### 3. 시대 배경을 판단 기준에 넣는다 — 무엇이 싸졌고 무엇이 안 싸졌나
"원샷이니 최소화"는 코드가 비쌌던 시절의 최적화였다.
지금 안 싸진 것: **데이터(중력 있음)**, **설계 판단(왜 이렇게 만들었나)**.
→ **점검**: "AI가 다시 만들면 되니까"가 통하는 영역(코드)과 안 통하는 영역(데이터·스키마·판단)을 구분한다.
   검증 안 된 기능의 빈 테이블은 미리 만들지 않는다(중력은 데이터가 실제로 쌓일 때 생긴다).

### 4. AI와의 토론은 "결정 대행"이 아니라 "선택지 정련"으로 쓴다
매 갈림길에서 AI가 표(장단점) + 기우는 쪽 + 확신도를 제시했고, **최종 결정은 내가 했다**
(Artist DB화, 공장 우선순위 등은 AI 권고와 다른 방향도 있었다).
→ **점검**: AI가 대신 정하게 두지 말 것. AI는 트레이드오프를 펼치는 데 쓰고, 결정의 주어는 나로 유지한다.

### 5. 측정선을 오염시키지 않는다
공장이 1순위라면 지켜야 할 건 "완료 → 측정 → 그다음 개선"의 순서다.
측정 전에 못 참고 고치면 개입 수가 "앱 문제 vs 내가 고친 것"으로 섞여 지표가 죽는다.
→ **점검**: AI 산출물을 받으면 개선 욕구가 먼저 든다. 그전에 성적부터 기록한다. (워딩: "센다"보다 "측정한다".)

---

## 좋았던 토론의 결(나중의 나에게)

- AI가 내 결정을 무조건 추인하지 않고, 확신도(%)를 붙여 반대 방향도 정직하게 폈다.
- 내가 던진 "원샷이니 최소화했어야 했나?"가 단순 질문에서 **"이 프로젝트를 제품으로 볼지 재료로 볼지"**라는
  더 큰 프레임으로 확장됐다. 좋은 질문 하나가 숨은 결정을 수면 위로 끌어올린다.
- 결국 기술 결정(테이블 몇 개)이 **커리어 전략(이직·이전 가능한 자산)**과 이어졌다.
  설계는 진공이 아니라 내 상황 위에서 정해진다.
