# 팩토리 공정 — 스펙 작성 방식 결정 (계기: W2 진입)

날짜: 2026-09-16. 성격: **팩토리(Y축) 공정 기록** — 특정 앱이 아니라 "스펙을 어떻게 쓸지" 공정 자체의 결정. W2 진입은 **계기일 뿐**, 이 문서엔 W2 앱 내용이 없다.
킥오프: `docs/w2-스펙설계-세션-킥오프.md`. 이 문서는 **방식만** 담는다 — W2 제품 내용(장면·격차)은 여기 안 쓴다(측정선 오염 금지, [[three-axis-job-change-frame]]).

---

## 0. 이 결정의 뿌리 (run1 근본원인)

run1 실패 = **격차 오판**: "장면이 진짜 원한 것(다중 말풍선)"과 "내가 배울 격차(토큰 스트리밍)"가 스펙 한 칸에 뭉쳐 종이 위에서 못 걸러졌다. → 스펙 쓰기 **전에** 이 둘을 갈라 깎아내는 단계가 있으면 이 실패를 앞단에서 잡는다.

## 1. 결정 (킥오프 Q1~Q3)

- **Q1 — 새 스킬/커맨드 짓나?** 안 짓는다. 기존 스킬 재사용. 효용성은 돌려보고 판정.
- **Q2 — 무게?** 경량(스펙트럼 a~b). pre-spec 게이트 한 단계 + 캡처. 워크플로/에이전트(d) 아님. n=1이라 무게 안 올린다.
- **Q3 — 팩토리 형태 방향 + 다음 한 스텝:** 팩토리가 앞에 **감산형 pre-spec 게이트**를 기르는 방향. 전체 설계는 미확정. 다음 한 스텝 = 아래 트라이 1회.

## 2. 확정한 방식 (W2 스펙 작성 파이프라인)

```
① 지연 brain-dump 거친 스케치 1장          (표적 = 지연 머릿속 가정)
② pre-spec 게이트 — 격차를 "하나로 깎기"    (감산: 새 요구 더하지 말고 덜어내기)
③ 살아남은 장면/격차를 S0에 캡처            (산출물 = 휘발 방지)
④ 기존 SPEC_TEMPLATE로 스펙 작성
⑤ (방향) 다 쓴 스펙을 grilling으로 QC 점검   ← 아직 미확정, 아래 참고
```

## 3. 스킬 역할 배치 (핵심 설계 판단)

- **deep-interview → ② 위쪽(구체화/추출).** 단 본능이 "끌어내기=확장"이라 지연 목적("가볍게 깎기")과 반대로 갈 위험. **미검증 → 트라이로 판정.**
- **grilling → ⑤ 아래쪽(스펙 문서 QC).** 본능이 "약점 파고들기"라, 거의 다 쓴 스펙에 대고 "원샷이 한 번에 못 끝낼 데·오버스펙 어디?"를 묻는 자리에 정확히 맞는다. run2의 "2턴버그 방지"를 종이 위에서 하는 것 = Y축 직결. **방향 채택, 확정은 뒤로.**

> 무게 규율: deep-interview·grilling을 **한꺼번에 넣지 않는다.** n=1이라 하나씩 증거 보고 채택.

## 4. 효용성 체크 기준 (이론 말고 측정)

- **deep-interview 판정:** "스케치를 **뾰족하게 깎았나**, **뚱뚱하게 불렸나**?" 깎으면 채택, 불리면 버리고 grilling만.
- **게이트 전체 판정(Y축):** W2에서 이 게이트가 스펙 쓰기 **전에** 격차/장면 mismatch(또는 오버스펙)를 **하나라도 잡아내나?** 잡으면 수렴 라운드를 산 것(n=1 증거), 못 잡으면 무게만 는 것.

## 5. 기록 분리 원칙 (이 세션에서 합의)

| 나온 것 | 어디로 |
|---|---|
| W2 제품 내용 (장면·격차·UX) | W2 스펙/로그 — 방식 트라이 중엔 **버릴 초안** |
| 방식 배움 (게이트가 깎나/부나, 수렴에 기여했나) | **회고行** (이 문서 계열) |

## 6. 다음 한 스텝

지연이 W2 거친 스케치를 brain-dump → deep-interview에 태워 **깎였나/불렸나** 판정. 이 1회가 곧 deep-interview 효용성 체크. (W2 실제 스펙 확정은 별도 세션 — [[scope-to-current-step]])

## 7. 트라이 결과 — deep-interview 효용성 체크 (같은 세션, 2026-09-16)

W2 거친 스케치를 deep-interview에 태워 부분 진행. 관찰:

- **Round 1: 깎였다 ✅** — 엉킨 음성기술 조각 5개(STT/TTS/왕복/오디오전송/전화UX)에서 **격차 1개(음성 왕복 STT→LLM→TTS)**로 감산. 나머지는 배경으로 밀림.
- **Round 2: 혼선** — "턴제 vs 스트리밍" 질문에 지연이 턴제를 골랐으나 곧 사고가 **넘쳤다**(무료크레딧 서비스 기억, 배움 vs 원샷, "스트리밍은 P2.5", "턴제가 통화로 자연스러운가"). deep-interview의 **점수·게이트 기계엔 이 교차축 고민을 담을 자리가 없었다.**
- **핵심 발견(메타):** 지연을 실제로 **깎아준 건 deep-interview의 모호도 점수가 아니라 3축(X장면/Y팩토리/Z배움)으로 갈라 채점해준 것**이었다. 홍수처럼 보인 고민이 한 선택에 3축이 동시에 당긴 것이었고, 축을 분리하니 수렴했다.
- **덤 성과:** 지연의 "진짜 스트리밍은 양방향" 통찰이 **장면/격차 어긋남**(워키토키 턴제는 '전화답지 않음')을 종이 위에서 드러냄 — run1식 오판을 pre-spec이 예방한 1건.

**잠정 판정:** deep-interview의 "한 질문·점수·게이트" 골격은 지연 사고 방식과 **대체로 직교(orthogonal)**. 진짜 감산 도구는 **3축 렌즈**다. → 향후 pre-spec 게이트는 deep-interview 기계보다 **"3축으로 홍수 가르기 + grilling식 감산"** 조합을 우선. deep-interview는 필요할 때 질문 소스로만 부분 차용.

> W2 제품 결정(격차 최종형)은 **버릴 초안**으로 별도. 선행조사 대상: 실시간 음성 API가 P2.5(WebRTC)와 겹치나·블랙박스인가, STT/TTS 지연·오디오 포맷. (실측 전 vibes 금지 — run1 재판 방지)

## 8. 상위 발견 — 팩토리 0단계 신설: "목적·축(점수판) 세우기"

이 세션에서 지연이 잡은 가장 큰 교훈. §7의 감산이 먹힌 이유를 일반화하면:

**축을 먼저 세워야, 뒤 단계(선행조사·pre-spec·스펙)가 vibes가 아니라 점수로 선택을 끊는다.**

오늘 우리는 3축 분리를 **홍수 한복판에서 사후적으로** 했다. 그게 진짜 감산 엔진이었다면, 애초에 **모든 것보다 먼저** 점수판을 세워야 한다.

### 팩토리 0단계 (깃털 — PRE-SPEC보다 앞)

> 세션 중 지연 교정: 축을 "세우는" 게 아니다 — 3축은 이미 상시 존재([[three-axis-job-change-frame]]). 0단계는 재정의 없이 **이번 작업용 tilt만** 잡는다. (처음 "축 ≥2개 세우기"는 과설계였음 — [[scope-to-current-step]])

- **산출물 (몇 줄)**: (1) 목적 한 줄, (2) **이번 작업 축 가중치 tilt** — 기본 Y>X>Z에서 벗어날 때만 명시(예: W2는 "2020 vs 2026 비교문서" 때문에 X가 평소보다 높음), (3) **축별 승리조건 한 줄씩**(이 작업에서 X-승/Y-승/Z-승이 뭔지).
- **왜 필요**: 축이 있어도 **깎는 순간에 안 갖다 대면** 소용없다(오늘 홍수가 증거). 자르기 전에 3축 채점을 강제해 vibes 대신 score로 끊는다.
- **왜 ≥2축**: 1축이면 단일 북극성 = Y편향 함정(run1). 2축↑라야 갈등이 "+X지만 −Z"로 점수화된다.

### 갱신된 파이프라인

```
0단계: 목적·축(점수판) 세우기   ← 신설. 여기서 판단 기준 확정
   → PRE-SPEC (API 선행조사)
   → pre-spec 게이트 (거친 스케치 → 3축으로 홍수 가르기 + grilling식 감산 → 격차 하나로)
   → SPEC_TEMPLATE (S0 장면·격차 → …)
   → 새 세션 one-shot
```
