| JD 키워드 | W2 근거 (코드/결정) | 면접 한 문장 (30초 답변 씨앗) |

## 2. X축 심화 — 트레이드오프 설명력 (시니어 시그널)

"무엇을 했나"보다 **"무엇을 안 했고 왜"**가 면접에서 급을 가른다. W2에서 의도적으로 버린 것들:

| 안 한 것 | 왜 (한 문장) |
|---|---|
| Realtime speech-to-speech | 왕복을 손으로 엮는 게 학습 목표 + 블랙박스·비용 회피 |
| 모노레포(서버/프론트 분리) | 로컬 PoC엔 단일 앱 custom server가 적합, 분리는 프로덕션 몫 |
| 바이트 스트리밍(MediaSource) | 문장 단위가 지연·자연스러움·구현난이도 모두 우위 |
| 모바일 웹 | HTTPS·wss 인프라 잡일이 격차와 무관, 모바일은 RN이 목표 |
| next 최신(16.3.5)을 15로 낮춤 → **정정** | *일반론보다 실측 우선* — w01 실측(16.3.5)로 되돌림 |

## 3. Z축 — 채운 빈 지식

- **실시간 음성 파이프라인**: STT(`/audio/transcriptions`, 발화 단위 파일 전사)·TTS(`/audio/speech`, mp3)·오디오 포맷(WebM/Opus 직송).
- **WebSocket 서버 운영**: Next 밖 custom Node server, `upgrade` 이벤트 라우팅, ws vs Route Handler의 근본 차이.
- **브라우저 미디어 제약**: `getUserMedia` secure context(localhost 예외), autoplay unlock 패턴, 클라 VAD 자작.
- **추론모델 파라미터**: `reasoning.effort:minimal`이 응답 토큰을 살려 "벙어리" 방지(통합테스트로 검증).

## 4. 능동 학습 — 면접 리허설 (지연 몫)

> §1·§2 표의 각 줄을 **소리 내어 30초 답변**으로 말해보기. 특히 §2(트레이드오프)는 "왜 안 했나"를 논리로 답할 수 있어야 함. 못 하는 줄 = 아직 안 내 것.

## 5. 다음 개발 고려사항 (이번 라운드 아님 — 메모)

- **아티스트별 목소리 선택**: `Artist` 모델에 `voice` 필드를 추가해 아티스트마다 TTS 목소리(성별·버전) 지정. 페르소나 DB 구조(`Artist.systemPrompt`)와 자연스럽게 맞물림. **선행 필요**: OpenAI TTS 모델의 voice 옵션·버전 조사(급하지 않음, 다음 라운드 전 확인). 지금 코드 직접 수정은 팩토리 측정선 밖이라 **다음 run 스펙 자산으로** 넣는다.
- **최종 제출 형태 = EC2 배포 공개 링크**: 웹 배포 + EC2 상주 서버로 누구나 테스트할 수 있는 링크 제공. **custom server 결정이 여기서 정합** — Vercel은 ws 상주 연결을 못 올리지만 EC2 자체호스팅은 됨(로컬 PoC 코드가 버릴 게 아니라 EC2로 이어지는 자산). HTTPS 확보로 **모바일 웹·마이크도 자동 해결**(ws→`wss` 승격만 챙기면 됨). 배포·운영은 뒤 단계(W6 관제판 근처/시즌 마무리) — 지금 아님.
