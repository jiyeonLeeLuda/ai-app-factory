성격: 결이가 정리한 개념 + **지연이 스스로 소화할 학습구간**(아래 §3).

## 1. 한 줄 요약

통화 앱 코드는 **두 종류**다 — ① 플랫폼 "손발"(마이크에서 소리 잡고 스피커로 트는 것) ② 통화 "두뇌"(언제 녹음을 끊고, 서버에 보내고, 문장 오디오를 순서대로 트는 것). **두뇌는 웹이든 앱이든 똑같고, 손발만 플랫폼마다 다르다.** 그 사이에 인터페이스(약속된 문틈)를 두면, RN으로 옮길 때 손발만 갈아끼우고 두뇌는 그대로 재사용한다.

## 2. 왜 그런가 (포트-어댑터 패턴)

**비유**: 두뇌 = 가전제품, 인터페이스 = 콘센트 규격, 어댑터 = 나라별 플러그. 가전(두뇌)을 새로 사지 않고 플러그(어댑터)만 바꿔 다른 나라(RN)에서 쓴다.

**섞어 짜면 생기는 일**: 통화 화면 컴포넌트 안에 `getUserMedia`·`MediaRecorder`·`<audio>`를 통화 로직과 뒤엉켜 넣으면 — RN은 이 브라우저 API가 **하나도 없어서**(`getUserMedia` 없음 → `react-native-webrtc`/`expo-av`), 포팅 때 그 컴포넌트를 통째로 다시 쓴다. 즉 **두뇌까지 재작성**.

**인터페이스로 자르면** (W2 스펙 채택안):

```ts
interface AudioCapture {
  start(): void
  stop(): void
  onUtterance(cb: (audio: Blob) => void): void  // 발화 하나 끝나면(VAD) 호출
}
interface AudioPlayer {
  unlock(): void              // 사용자 클릭 때 1회 (autoplay 해제)
  enqueue(audioUrl: string): void  // 문장 오디오를 재생 큐에 추가
}
```

| | 웹 어댑터 (W2) | RN 어댑터 (W2.9) |
|---|---|---|
| `AudioCapture` | getUserMedia + MediaRecorder + 자작 VAD | react-native-webrtc / expo-av 녹음 |
| `AudioPlayer` | `<audio>` 엘리먼트 큐 순차재생 | 네이티브 오디오 재생 |
| **통화 두뇌** | `onUtterance`→ws 전송 / 서버 문장오디오→`enqueue` | **동일 코드 그대로** |

통화 두뇌(턴 관리·ws 송수신·재생 순서 제어)는 **인터페이스에만 의존**하므로 웹/RN 무관하게 재사용된다.

## 3. 학습구간 — 지연이 스스로 채울 것 (능동 학습)

> 읽기만 하면 안 남는다. 아래를 직접 해보면 스키마로 굳는다.

**① 숲: 나눠보기.** W2 통화 기능을 종이에 쓰고, 각 조각을 "웹/RN 공통(두뇌)" vs "플랫폼마다 다름(손발)"으로 직접 분류해봐. (힌트: VAD 로직은 어느 쪽? ws 프로토콜은? 재생 "순서" 관리는? 실제 소리 재생은?)

**② 줌인: 매핑표 채우기.** 위 §2 표의 빈칸을 안 보고 다시 그려봐 — 인터페이스 3개 메서드(`onUtterance`/`unlock`/`enqueue`)가 웹에선 어떤 API로, RN에선 어떤 API로 구현될지.

**③ A:B 대조.** "안 나누고 컴포넌트에 다 넣은 버전"을 상상하고, W2.9 포팅 날 **정확히 무엇이 터지는지** 한 문단으로 써봐. (이게 분리의 가치를 역으로 증명)

**④ 설명 리허설.** 면접관에게 한 문장으로: *"왜 오디오 캡처를 인터페이스로 분리했나요?"* → 30초 답변 만들어보기. (X축 자산으로 직결 — 포트-어댑터/헥사고날 아키텍처를 실제 선택 근거로 말할 수 있으면 시니어 시그널)

**⑤ 동화 점검.** 이 패턴을 이미 아는 다른 것과 연결 — 예: W1에서 "LLM 모델을 env로 주입"한 것도 같은 원리(구현을 갈아끼우게 경계를 둠)인가? 리포지토리 패턴은? (같으면 왜, 다르면 왜)

## 4. 핵심 못 (기억할 것)

- **플랫폼 경계는 인터페이스로 봉인한다.** 종속 API(getUserMedia 등)가 로직에 스며들면 포팅 비용이 폭발.
- W2는 웹 어댑터만, W2.9는 RN 어댑터만 — **두뇌는 한 번만 쓴다.**
- 이건 "포트와 어댑터(헥사고날) 아키텍처"의 작은 실전 적용. 이름을 알아두면 면접에서 근거로 쓴다.
