# W2.5 Z축 회고 — three.js 생태계 버전 핀 & 번들링 (원샷 리스크 방어)

날짜: 2026-09-17. 성격: **Z축(빈 지식) + Y축(원샷 리스크 방어) 회고** — SPEC 발사 직전 "three.js가 까다로웠던 기억"(지연)에서 출발해 버전 충돌을 종이 위에서 잡은 기록. [[three-axis-job-change-frame]]
깊이: **1차(핀 확정 + 함정 지도)**. 번들러 내부·색공간 breaking 등 세부는 나중에 더 판다.

---

## 0. 왜 발사 전에 버전을 못박았나

three.js 생태계는 **버전 충돌이 유난히 흔하다** — three가 r150대에서 색공간(`LinearEncoding`→`LinearSRGBColorSpace`, r152)·빌드 방식을 깨는 변경을 자주 내서, three-vrm이 그걸 따라잡는 버전이 정해져 있다. three + three-vrm + mediapipe 3개 조합은 원샷이 헤매기 쉬운 지점 → 스펙 체크리스트 0b("깨지기 쉬운 핵심 패키지는 버전을 못 박는다")를 발사 전에 적용했다.

## 1. 확정 핀 (package.json)

```json
"three": "0.180.0",
"@pixiv/three-vrm": "3.5.5",
"@mediapipe/tasks-vision": "1.0.1",
"@types/three": "0.180.0"
```

- `^` 없이 **정확 고정**. 이유는 §2.

## 2. 핵심 교훈 — "peer 범위 통과 ≠ 실측 검증"

- `@pixiv/three-vrm@3.5.5`의 peer는 `three >=0.137`(하한만, 상한 없음). 그래서 three `latest`(0.186.0)도 **형식상 통과**한다.
- 그런데 three-vrm 팀이 **devDependencies에서 실제 테스트한 three는 `^0.180.0`**(README importmap도 0.180). 0.186은 peer는 통과하나 three-vrm이 **실측한 근거가 없다**.
- → **latest를 믿지 말고, 업스트림이 실측한 버전으로 내린다.** `^` 고정하면 자동 마이너 업데이트로 미검증 조합(0.181+)이 조용히 유입되므로 **정확 버전 고정**.
- 일반 규칙: 라이브러리 궁합은 "내 최신 취향"이 아니라 **의존 라이브러리가 검증한 버전**에 맞춘다. (W2 "일반론보다 실측 우선"의 의존성판 — [[evidence-over-generic-advice]])

## 3. "three가 까다로웠다"의 정체 — 상당수가 react 결합이었다

- three·three-vrm·@mediapipe/tasks-vision 모두 **react 무의존**(순수 WebGL/WASM). next 16.3.5의 react(18 또는 19)와 **충돌 지점이 없다**.
- three가 까다롭게 느껴졌던 기억의 큰 부분은 **`@react-three/fiber`**(three를 react 렌더 트리에 묶는 래퍼) — fiber는 react 버전·동시성 모드에 민감하다.
- 이번 스펙은 **순수 three + `useEffect` 직접 초기화**(fiber 미사용) → 그 까다로움의 축을 애초에 제거했다.

## 4. 번들링 함정 (Next 16 + three ESM)

- three는 **ESM 전용** → `require()`면 `ERR_REQUIRE_ESM`. `useEffect` 안에서 `import`로 쓴다.
- 로더 경로 = **`three/addons/loaders/GLTFLoader.js`** (three 0.152부터 package.json `exports`에 `three/addons` 공식 등록. `three/examples/jsm/`로 alias). Next 16 기본 번들러 **Turbopack**·webpack 모두 유효.
- `transpilePackages: ['three']`는 **필수 아님**(three가 raw TS를 ship 안 함). Turbopack이 `three/addons/` resolve에 실패할 때만 추가.
- SSR 크래시(`window` 없음)는 `next/dynamic({ ssr:false })` + `'use client'` + `useEffect`로 처방(S4).

## 5. 나중에 공부할 것 (지연 몫)

- [ ] Turbopack vs webpack의 **ESM 처리·resolve 차이**, `three/addons` alias가 실제 어떻게 풀리나
- [ ] three r152 **색공간 breaking**(Linear→SRGB)이 렌더 결과에 준 영향, three-vrm이 어떻게 흡수했나
- [ ] `@react-three/fiber`를 쓸 때/안 쓸 때 트레이드오프(선언적 씬 vs 직접 제어)
- [ ] tree-shaking·번들 사이즈(three는 무거움 — W3 씨앗의 모델 경량화와 연결)
- [ ] semver를 안 지키는(r단위 breaking) three의 버전 정책과 대응 관행

## 핵심 못

- **latest ≠ 안전. 의존 라이브러리가 실측한 버전이 안전.** (`three@0.180.0` ← three-vrm devDep)
- `^` 없이 정확 고정으로 미검증 조합의 자동 유입을 막는다.
- "three 까다로움"의 큰 축은 **react 결합(fiber)** — 순수 three면 그 축이 사라진다.
