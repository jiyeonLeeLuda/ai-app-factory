# 스펙 작성 시 고려할 점 (공장 프로세스)

작성: 2026-09-16. 목적: SPEC.md를 쓰기 **전에** 반드시 통과할 선행 점검. one-shot에 넣을 스펙의 품질이 공장 지표를 좌우하므로, 스펙 작성은 즉흥이 아니라 이 체크리스트를 따른다.

계기: P1 데이터 모델을 다 짜고 나서야 "`role`은 내 설계가 아니라 LLM API가 강제하는 규격"임을 알게 됐다. **API를 모르고 스펙을 쓰면 나중에 갈아엎는다.** 그 마찰을 프로세스로 방어한다.

---

## 0. 스펙 쓰기 전 (PRE-SPEC) — API·기술 선행조사

> "무엇을 만들지"보다 "무엇 위에서 만드는지"를 먼저 안다. 이게 없으면 스펙이 헛돈다.

- [ ] **쓸 API/SDK를 확정**했는가? (예: OpenAI vs Claude — 이름만 비슷하고 규격·모델명·인증이 다르다)
- [ ] 그 API의 **고정 규격**을 확인했는가 — 내 자유가 아니라 API가 정한 것들:
  - 메시지 역할 어휘 (`system`/`user`/`assistant`/`tool` 등 — 이름 못 바꿈)
  - 스트리밍 방식과 응답 청크 형태 (SSE? 델타 필드 이름?)
  - 인증 방식·환경변수 이름 (`OPENAI_API_KEY` 등)
  - 모델 이름 (내 기억으로 쓰지 말 것 — **현재 공식 문서에서 확인**. 모델명은 자주 바뀐다)
  - 요청 파라미터 (max_tokens, temperature 등)와 상한
- [ ] **비용·한도**를 확인했는가 — 호출당 토큰 과금, rate limit, 컨텍스트 윈도우.
- [ ] 이 조사 결과가 스펙의 S4(비기능 제약)에 **구체적 값으로** 반영되는가?

원칙: **API 지식은 내 기억이 아니라 공식 문서에서 가져온다.** AI(나 포함)도 모델명·최신 규격은 틀릴 수 있으니 문서로 검증한다.

### 0b. 실행 환경·의존성·보안 (P1 원샷에서 데인 것)

- [ ] **의존성 버전 핀** — 특히 `prisma@6`(7+는 클래식 워크플로우 폐기). `latest`/RC가 원샷을 헤매게 한다. 깨지기 쉬운 핵심 패키지는 메이저 버전을 스펙에 못 박는다.
- [ ] **사람 준비물은 "검증 명령"으로 확인 가능하게** — 글로만 적으면 "했다고 생각했는데 안 됨"(팬텀 준비물)이 조용히 숨는다. 예: DB role 존재를 프리체크로 확인, 없으면 멈추고 정확한 명령 안내.
- [ ] **원샷은 최소권한·격리에서** — 로컬 `trust` 인증이면 자율 에이전트가 슈퍼유저로 자가승격 가능(P1에서 확인). role 자가 생성 금지, 가능하면 샌드박스/컨테이너·전용 제한 계정으로 실행. (근본 해결은 W5 Factory 개선)

## 1. 장면·격차 (S0)

- [ ] 장면이 한 문장으로 그려지는가? (누가, 무엇을 하는 화면)
- [ ] 격차가 **하나**인가? 여러 개면 장면이 죽는다.

## 2. 데이터 모델 (S2) — 무엇이 싸졌고 무엇이 안 싸졌나

- [ ] 각 엔티티가 "**곧 진짜 데이터가 쌓이나?**"를 통과하는가?
  - 쌓인다 → 지금 제대로 모델링 (데이터엔 중력이 있어 나중 마이그레이션이 비싸다)
  - 안 쌓인다 → **빈 테이블 만들지 말 것.** 미래 후보로 메모만 (예: 메모리·이벤트·RAG 테이블)
- [ ] **API 계약**과 **UI/도메인 개념**을 구분했는가?
  - 예: `role`(API 계약, 못 바꿈) ≠ 말풍선 정체성(도메인, 관계에서 파생)
- [ ] 표시용 정보를 **복제 저장**하려 하는가? → 관계에서 그때그때 읽어라 (복제하면 낡음(stale) 버그)
- [ ] 지금 익명/단일이라 **채울 컬럼이 없는 테이블**을 만들려 하는가? → 미룬다

## 3. 엣지 케이스 (S3)

- [ ] 비어 있을 때 / 실패할 때 / 큰 입력 / 동시 발생 — 네 가지를 각각 적었는가?
- [ ] 실패 시 **더러운 데이터를 남기지 않는** 규칙이 있는가? (예: 실패한 응답은 DB에 저장 안 함)

## 4. 검증 (S5) + Acceptance

- [ ] AI가 **스스로 돌려 확인**할 명령이 있는가? (typecheck/lint/build/validate/seed)
- [ ] 자동 검증이 **못 잡는 것**(스트리밍 체감·페르소나 톤)을 사람 체크(Acceptance)로 옮겼는가?
- [ ] "빌드는 되는데 실제론 안 되는" *틀린 보고*를 걸러낼 체크가 Acceptance에 있는가?

## 5. 경계 (Out of Scope)

- [ ] 이번 주 안 하는 것을 명시했는가? 스트레치는 "(스트레치)"로 구분했는가?

## 순서 요약

**PRE-SPEC(API 선행조사) → S0 장면·격차 → S1 UX → S2 데이터 모델 → S3 엣지 → S4 제약 → S5 검증 → Acceptance → Out of Scope → 사람 승인 → 새 세션 one-shot**

PRE-SPEC을 건너뛰면 S2에서 반드시 되돌아온다. (P1에서 실제로 그랬다.)
