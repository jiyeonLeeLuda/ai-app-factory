# W3 선행조사 — AI 아바타 영상통화 (PRE-SPEC)

조사일: 2026-09-17. 출처: 공식/권위 문서(OpenAI 플랫폼 문서·MDN Web Audio·W3C Web Audio spec). **모델명·규격·구현은 기억이 아니라 문서에서.**
목적: W3 스펙의 신규 표면(① LLM emotion 구조화 출력 ② TTS 오디오 진폭 립싱크)만 조사한다. STT/LLM/TTS 왕복·문장단위 TTS·custom ws 서버는 **W2에서 이미 조사·실측 통과**(metrics `w02`=pass)라 재검증 안 하고 재사용한다.

> 조사 방식: 서브에이전트 2대(공식문서 웹조사, 기억 금지)로 병렬 조사. 아래는 결정에 필요한 확정 사실만 요약.

## 1. LLM emotion 구조화 출력 — **씨앗의 "JSON"을 정정한다** (핵심 발견)

씨앗은 파이프라인을 `LLM(JSON {text, emotion} 구조화 출력)`으로 적었다. 조사 결과 **이 문자 그대로 가면 W2의 지연 트릭이 깨진다.**

### 확정 사실

- OpenAI Responses API는 **Structured Outputs**(JSON Schema 강제)를 지원한다(`text.format`의 `json_schema`). 출처: OpenAI 플랫폼 문서 — Structured Outputs / Responses API.
- **긴장점(핵심):** `stream: true`와 json_schema를 함께 켜도, 스트림은 **JSON 직렬화 문자열이 토큰 조각으로 흘러온다**(필드명·값이 뒤섞인 raw fragment). **필드 단위 스트리밍이 아니다.** 즉 `text` 필드를 문장 단위로 조기에 뽑으려면 **부분 JSON 파서를 직접** 붙여야 하고, 사실상 **JSON 객체가 닫힐 때까지 기다려야** 온전한 `text`를 얻는다.
- W2의 지연 승부수 = **"첫 문장 경계가 나오는 즉시 그 문장 TTS를 태운다"**(발화→첫 소리 지연 단축). strict JSON은 이 트릭을 무력화한다 → 통짜 대기로 회귀 → 전화답지 않은 지연.

### 결정 — **구분자(delimiter) 프로토콜** (strict JSON 폐기)

`{text, emotion}`를 얻되 스트리밍을 지키는 가장 단순·견고한 길:

- **응답 첫머리에 emotion 태그 1개**를 고정 형식으로 뱉게 지시한다: `[[happy]]` 처럼 `[[emotion]]` (emotion ∈ `happy|angry|sad|relaxed|surprised|neutral`) → 그 뒤로 자연스러운 구어체 발화.
- 서버는 W2대로 토큰 스트리밍을 받되, **선두 `[[...]]` 태그가 닫힐 때까지만 버퍼**(첫 몇 토큰), emotion을 파싱해 클라에 즉시 `{type:'emotion'}`로 전송, 태그를 떼어낸 **나머지 텍스트는 W2의 문장분할→TTS 파이프라인에 그대로** 흘린다. → **지연 트릭 보존 + emotion 획득.**
- **폴백(견고성):** 첫 ~24자 안에 유효 태그가 없으면 `emotion=neutral`로 두고 전체를 발화로 처리. (모델 미준수 시 무음/크래시 방지 — gpt-5-nano도 "짧은 구어체" 지시를 W2에서 잘 따랐고, 선두 고정 태그는 더 쉬운 지시.)
- **1응답=1 emotion**(first-pass). 문장별 emotion 전환은 스트레치.

> 왜 이게 P1 `role` 교훈의 재현인가: "API를 모르고 스펙을 쓰면 갈아엎는다." 씨앗의 'JSON' 표현을 그대로 스펙에 박았으면 원샷이 strict-JSON-스트리밍의 지연 함정에 빠졌을 것. **선행조사가 스펙을 정정한 1건.** (일반론<실측 — memory)

- `reasoning: { effort: "minimal" }`(gpt-5-nano 무응답 방지, W2 실측)는 그대로 유지. 구분자 프로토콜은 순수 instruction-following이라 reasoning effort와 무관.

## 2. TTS 오디오 진폭 → 입(`aa`) 립싱크 (Web Audio)

목표: 재생 중인 TTS mp3의 **음량**으로 VRM `aa`(입 벌림 0..1)를 실시간 구동. "적당히 오물오물" 수준(정밀 비짐 동기화는 범위 밖 — 씨앗).

### 확정 사실 (MDN / W3C Web Audio API)

- 그래프: `AudioContext` → `createMediaElementSource(audioEl)`(= `MediaElementAudioSourceNode`) → `AnalyserNode` → **`audioContext.destination`**. rAF 루프에서 `analyser.getByteTimeDomainData(buf)`로 파형을 읽어 **RMS**(√(Σ(x−128)²/N)/128) → 음량 0..1. 출처: MDN `AnalyserNode`, `AudioContext.createMediaElementSource`.
- **시간영역(getByteTimeDomainData)이 이 용도에 맞다** — "말소리 크기 = 입 벌림"은 파형 진폭(RMS)이 자연스럽다. 주파수영역(getByteFrequencyData)은 비짐/포먼트 분석용이라 과함.

### 함정 3종 (스펙에 못박아 원샷이 무음·throw 안 겪게)

1. **`createMediaElementSource(el)`는 element당 정확히 1회.** 두 번 호출하면 throw. → 오디오 엘리먼트 **하나를 앱 수명 내내 재사용**하고(문장마다 `src`만 교체 — W2 결정과 동일), 소스 노드도 **최초 1회만** 생성해 유지. (문장마다 `new Audio()` 금지 = W2 iOS 함정과도 일치.)
2. **소스를 analyser로 라우팅하면 `destination`에도 반드시 connect** — 안 하면 **소리가 안 남**(analyser만 물리면 무음). 출처: MDN `createMediaElementSource` 주의.
3. **CORS 오염:** cross-origin 오디오를 `createMediaElementSource`에 물리면 보안상 analyser가 **0(무음 데이터)** 을 돌려줘 립싱크가 죽는다. 출처: W3C Web Audio API — Security/Privacy(cross-origin media). → **mp3를 자기 서버(same-origin) 또는 `blob:` URL로** 서빙하면 안전(TTS mp3는 우리 서버가 ws로 보내 클라가 Blob→objectURL로 재생하므로 same-origin/blob → 오염 없음).
4. **AudioContext는 사용자 제스처 후 `resume()`** — autoplay 정책. 앱은 이미 "통화 시작" 클릭에서 무음 `<audio>`를 unlock(W2 자산)하므로, **같은 클릭 핸들러에서 `audioContext.resume()`** 도 호출. (W2 오디오 unlock과 한 제스처에 묶는다.)

### `aa` 매핑·스무딩

- RMS는 보통 작다(대략 0..0.3). `aa = clamp(rms * GAIN, 0, 1)`(GAIN≈3~5, 튜닝 노브) 후 **lerp 스무딩**(`aa += (target-aa)*0.3`)으로 지터 억제.
- **재생 정지/종료 시 `aa`→0**(입 다물기): `audioEl.paused || ended`면 target=0.

### 대기(idle) 애니메이션 (씨앗 §대기상태 — 경량)

- 말 안 할 때: **주기적 blink**(2~5s 랜덤 간격, 0.1s 감음)과 **미세 호흡**(head/chest 본에 저진폭 sine, 예 `sin(t)*0.02`). 시간 기반이라 트래킹 불필요. POC 수준.

## 3. 재사용 확정 (W2·W2.5 자산 — 재조사 안 함)

- **STT**: `gpt-4o-mini-transcribe`, `/audio/transcriptions`, 발화단위 webm 파일 전사, 25MB 상한 (W2 확정·pass).
- **LLM**: OpenAI Responses API, `gpt-5-nano`(env), `reasoning.effort:"minimal"`, `stream:true`, `instructions`=페르소나+통화맥락, `max_output_tokens:1000` (W2 확정·pass). 위 §1 구분자 프로토콜만 추가.
- **TTS**: `gpt-4o-mini-tts`, `/audio/speech`, **mp3**, 문장단위 생성→순차 재생(단일 `<audio>` 재사용) (W2 확정·pass).
- **VRM 렌더**: three.js + `@pixiv/three-vrm`, `expressionManager.setValue` + head bone, 얼굴 클로즈업(`CAM_DIST≈0.55`), A포즈 팔 고정 (W2.5 `characterRenderer.ts`·pass). W3는 **구동 소스만 교체**(웹캠→오디오/emotion).
- **서버/전송**: custom Node **https** server + `ws`(오디오 릴레이), mkcert 내부망 HTTPS, Secure 쿠키, `allowedDevOrigins` (W2/W2.5 자산). ※ W3는 1인 사용(팬↔서버)이라 **2번째 기기 불필요** — 자동검증·실측 모두 노트북 1대 localhost로 가능. 내부망 HTTPS/폰은 **모바일 UX 확인용 선택**(P2P였던 W2.5보다 단순).

## 4. 스펙 S4에 넣을 확정값 (요약)

- **emotion 획득 = 구분자 프로토콜**(`[[emotion]]` 선두 태그, strict JSON 폐기), 1응답=1 emotion, 무효 시 neutral 폴백.
- **립싱크 = MediaElementSource(1회)→AnalyserNode→destination, time-domain RMS→lerp→`aa`**, GAIN≈3~5, 정지 시 aa→0, same-origin/blob mp3, AudioContext.resume는 시작 제스처에서.
- **emotion 표정 = LLM emotion → VRM 표정 1:1 lerp(~0.3s)**, 집합 `happy|angry|sad|relaxed|surprised|neutral`.
- 나머지 STT/LLM/TTS/서버 = W2/W2.5 확정값 그대로.
