# SPEC — AI 음성통화 (W2)

> 작성: 2026-09-17. 재료: `docs/w2-prespec-씨앗.md`(주 재료) + `docs/w2-이어하기.md`(핸드오프).
> 방식 근거: `docs/회고/2026-09-16-팩토리-스펙작성방식-결정.md`(감산형 pre-spec 게이트).
> spec_variant: S1+S2+S3+S4+S5
>
> **이 파일 하나만 새 세션에 투입해 one-shot 실행한다. 단, 원샷은 2부 구조다:**
> - **1부** — 빈 `apps/w02-voice-call/` 폴더에서 **W1 SPEC(`docs/p1-spec.md`)을 그대로 실행**해 검증된 채팅 앱을 세운다. (W1 재현 = 팩토리 회귀 테스트)
> - **2부** — 그 위에 이번 주 격차인 **음성 통화**를 얹는다. 이 SPEC 본문은 **2부만** 상세히 규정하고, 1부는 p1-spec.md에 위임한다.
>
> **사람 준비물 (원샷 시작 전)** — W1과 동일, 새 prereq 없음:
> ① Postgres 기동 (`pg_isready`), ② `CREATEDB` 권한 role(예: `factory`),
> ③ `factory/.env.shared`에 `OPENAI_API_KEY` + `CREATE_DB_URL`,
> ④ Node 런타임. → `OPENAI_API_KEY` 하나로 STT·LLM·TTS 전부 커버(별도 키 없음).

## S0. 장면 (필수)

팬이 채팅방에서 **전화를 걸면**, 아티스트(필립)가 "여보세요?" 하고 **먼저 음성으로** 받고, 팬이 말하면 그 음성이 실시간으로 전사→응답→음성으로 돌아오는 **통화 화면**.

## S0. 격차 (필수)

**음성 왕복 STT→LLM→TTS를, 브라우저↔서버 WebSocket 릴레이로 직접 엮기.**
경로 = **A안 Chained**(통짜 Realtime API 아님): 브라우저 mic → ws → Next.js 서버 릴레이 → `gpt-4o-mini-transcribe`(STT, HTTP) → LLM(W1 재사용) → `gpt-4o-mini-tts`(TTS, HTTP) → ws → 브라우저. **턴 종료(침묵) 감지(VAD)도 직접 구현**한다.

## S1. 사용자 경험 서술

W1 흐름(가입/리스트/채팅방/스트리밍)은 **1부에서 그대로 산다**(p1-spec.md S1). 2부가 더하는 것만 서술한다.

1. **통화 진입**: 채팅방 우상단 햄버거(또는 통화 아이콘) 버튼 → "전화 걸기" → 통화 화면으로 이동. (메신저 앱의 통화 진입과 동일한 감각)
2. **연결**: 통화 화면이 뜨면 짧은 신호음(연결음) 후 "연결됨" 상태로 전환. 아바타·이름·통화 경과 시간·통화 상태(연결중 / 말하는 중 / 듣는 중)를 표시. **자막 없음 — 화면의 주인공은 음성**(run1 "타이핑≠말풍선" 교훈 반영, 순수 전화 경험).
3. **첫 턴 = 아티스트 선턴**: 연결되면 사용자 입력 없이 **아티스트가 먼저** "여보세요? / hello?"를 **TTS 음성으로** 재생한다. (W1은 user 선턴 — W2에서 뒤바뀜)
4. **말하기(사용자 턴)**: 사용자가 말하면 mic가 받는다. **침묵이 일정 시간 이어지면(VAD) 발화 종료로 보고** 그 발화를 서버로 보낸다. 화면은 "듣는 중"으로 표시.
5. **응답(아티스트 턴)**: 서버가 전사→응답→음성 생성을 거쳐 오디오를 돌려주면, 도착하는 대로 **스트리밍 재생**한다(첫 소리까지 지연 최소화). 화면은 "말하는 중".
6. **통화 종료**: "끊기" 버튼을 누르면 ws 연결을 닫고 채팅방으로 돌아간다. **통화 내용은 저장되지 않는다**(휘발). 새로고침·이탈 시에도 통화는 종료된다.

## S2. 데이터 모델

**W2는 새 테이블을 추가하지 않는다.** W1 스키마(User/Artist/Conversation/Message)는 1부에서 그대로 생기고(p1-spec.md S2), 2부는 그 위에 얹힌다.

- **통화는 휘발 — DB 미저장.** 전사 텍스트도, 오디오 blob도, 턴 히스토리도 저장하지 않는다. → W1 텍스트채팅=영속 / W2 통화=휘발, 결이 다르다.
- **통화 내 턴 히스토리는 서버 세션 메모리로만** 유지한다. ws 연결이 살아있는 동안만 `[{role, content}]` 배열로 들고 LLM `input`에 실어 맥락을 잇고, 연결이 끊기면 소멸한다.
- **아티스트 페르소나는 W1의 `Artist.systemPrompt`(DB)를 재사용**한다. 통화용으로 별도 row를 만들지 않되, LLM 호출 시 "지금은 전화 통화 중 — 짧고 자연스러운 구어체로 말한다"는 맥락을 `instructions`에 덧댄다(S4).
- **auth 미룸**: W2도 W1과 동일하게 쿠키 세션(`userId`)만 쓴다. 통화는 로그인 없이 채팅방에서 바로 건다. (진짜 auth는 W4 직전 슬롯 — p1-spec.md S2c)

## S3. 엣지 케이스

W1 엣지(빈 대화·중단·쿠키 분실 등)는 1부가 커버(p1-spec.md S3). 2부 음성 엣지만:

- **STT 빈 결과**: 전사 결과가 비었거나 공백/노이즈만이면 그 턴을 **버리고 다시 듣는 중으로 복귀**(아티스트가 응답을 지어내지 않음). 필요 시 "잘 안 들렸어, 다시 말해줄래?" 짧은 재청 프롬프트.
- **침묵 타임아웃**: 연결 후 오래(예: 10초+) 아무 발화가 없으면 아티스트가 짧게 말을 걸거나("여보세요? 듣고 있어?"), 그래도 반응 없으면 통화 유지한 채 대기(끊지 않음).
- **mic 권한 거부**: `getUserMedia` 거부/실패 시 통화 화면에서 **명확한 안내 + 재요청 버튼**, 통화는 시작하지 않음(빈 통화로 진입 금지).
- **통화 중 새로고침·이탈**: 페이지 언로드 시 ws를 닫고 서버 세션 메모리를 정리한다. 재진입은 새 통화(이전 맥락 없음 — 휘발이므로 정상).
- **네트워크 끊김 / ws 끊김**: ws 연결이 끊기면 통화 화면에 "연결 끊김" 표시 + 재연결 또는 종료 선택. 진행 중이던 턴은 폐기.
- **STT/TTS/LLM API 실패**: 해당 턴을 실패 처리하고 짧은 오류 상태 표시 후 다시 듣는 중으로 복귀(통화 자체는 유지). 부분 오디오는 남기지 않음.
- **긴 응답 = 비싼 오디오**: `max_output_tokens`(S4)로 상한. 페르소나가 짧게 끊어 말해 1000토큰 독백·긴 TTS 과금을 방지.
- **동시 턴**: 아티스트가 "말하는 중"일 때 들어온 사용자 발화는 큐잉하지 않고, 현 턴 완료 후 다음 발화를 받는다(한 번에 한 턴 — 진짜 barge-in은 Out of Scope).

## S4. 비기능 제약

- **스택 고정**: W1과 동일(Next.js App Router + TypeScript + Prisma + Postgres, Node 런타임). pgvector 불필요.
- **전송 = WebSocket**: 브라우저↔서버 오디오 릴레이는 ws. Next.js App Router의 Route Handler는 ws 서버를 직접 호스팅하지 못하므로 **custom Node server(http + `ws` 라이브러리)** 로 띄운다. `dev`/`start`가 이 custom server를 타도록 구성. (P2.5는 WebRTC — 겹침 없음)
- **STT**: `gpt-4o-mini-transcribe`, HTTP `/audio/transcriptions`. **실시간 ws 전사가 아니라 발화 단위 파일 전사**다(씨앗 §3 — 지목 모델은 HTTP 전용). 서버가 ws로 받은 발화 오디오를 이 엔드포인트에 파일로 보낸다.
- **VAD(턴 종료 감지) = 클라이언트에서 직접 구현**: 브라우저 Web Audio API로 볼륨/침묵을 감지해 발화 종료를 판정하고, 그 발화 오디오만 ws로 전송한다. 무거운 VAD 라이브러리 대신 볼륨 임계 + 침묵 타이머 수준의 자작(배움 Z 보존). 임계·침묵 길이는 상수로 두고 실측 후 조정.
- **LLM**: W1 것을 재사용(OpenAI Responses API, 모델은 env 주입 — 기본 `gpt-5-nano`). `instructions` = `Artist.systemPrompt` + "전화 통화 중, 짧고 자연스러운 구어체" 맥락. `max_output_tokens: 1000`(W1과 동일). 히스토리는 통화 세션 메모리 배열을 매 턴 `input`에 실음.
- **TTS**: `gpt-4o-mini-tts`, HTTP `/audio/speech`. **출력 포맷 mp3, 스트리밍 재생**(도착하는 청크부터 재생). voice는 필립용으로 하나 고정(env 또는 상수). ⚠️ 스트리밍 재생은 오디오 버퍼링/MediaSource 처리로 원샷 난이도가 오른다 — S6 함정 참고.
- **오디오 포맷**: 입력 = 브라우저 MediaRecorder **WebM/Opus**, 출력 = TTS **mp3**.
- **언어**: ko/en 혼용 허용("여보세요/hello"). STT `language` 강제하지 않음(자동), 페르소나는 한국어 기본.
- **Realtime API 의도적 미사용**: `gpt-realtime` speech-to-speech 통짜는 **쓰지 않는다**. 근거 — ① STT→LLM→TTS 왕복을 손으로 엮는 게 이번 격차(배움 Z), ② 데이터 소유·벤더 독립(왕복 블랙박스 회피), ③ 비용(Realtime 오디오 $10/$20 per 1M vs Chained 경량).
- **의존성 핀**: W1 핀 유지(`prisma@6`·`@prisma/client@6`, `latest`/RC 금지). 추가로 `ws`(WebSocket 서버), OpenAI SDK는 W1과 동일 버전. 새로 넣는 패키지도 메이저 고정.
- **배포 제약**: Vercel serverless는 상주 ws를 호스팅하지 못하고, 지원 경로도 세션 한계(Hobby 5분/Pro ~13분)가 있다. **W2는 로컬 학습 PoC** — 프로덕션 배포는 Out of Scope(상주 서버는 후속).
- **시크릿**: `OPENAI_API_KEY`는 서버에서만 사용. STT/LLM/TTS 호출 전부 서버 경유 — 키를 클라이언트로 절대 노출 금지(오디오도 ws로 서버가 중계).

## S6. 원샷 실행 규칙 (2부 부트스트랩)

원샷이 스스로 하는 것 (사람 준비물 위에서). **1부 → 2부 순서로 이어서 실행하되, 큰 틀은 하나의 원샷이다.**

**폴더 구조 (2부 완성형)** — 앱은 **분리하지 않는다**. 하나의 Next 앱을 custom Node server로 감싸는 단일 구조. `server.ts`가 **문지기**: HTTP 요청은 Next 핸들러로, `/ws` 업그레이드만 ws 핸들러로 갈라 보낸다.

```
apps/w02-voice-call/
  server.ts            # custom 시동 = 문지기. http.createServer로 뜨고
                       #   - 일반 요청 → Next request handler에 위임
                       #   - 'upgrade' 이벤트(/ws) → ws 핸들러로 라우팅
  app/
    (chat)/…           # 1부: W1 채팅 화면 그대로 (p1-spec.md S1)
    call/[artistId]/   # 2부: 통화 화면 (클라 컴포넌트: mic 캡처·클라 VAD·오디오 스트리밍 재생)
  lib/
    ws/                # ws 연결·업그레이드 처리·연결별 턴 라우팅
    voice/             # STT→LLM→TTS 파이프라인 + 통화 세션 메모리(연결별 [{role,content}])
    …                  # W1 lib (prisma client, openai client 등) 재사용
  prisma/              # 1부가 만든 스키마·seed 그대로 (W2 새 테이블 없음)
  package.json         # dev/start 스크립트가 반드시 server.ts를 타게 (next dev 직접 아님)
```

> 왜 단일 구조인가: ① 1부가 W1 단일 Next 앱을 재현하므로 쪼개면 재현이 깨진다, ② 단일 격차·원샷 가벼움 목표에 모노레포는 오버엔지니어링, ③ 프론트/서버가 같은 배포단위·타입 공유. (ws를 상주 서버로 떼는 분리는 프로덕션 몫 — Out of Scope. 위 `lib/voice` 경계를 미리 그어두면 후속 분리도 쉽다.)

**0. 프리체크**: `CREATE_DB_URL`로 Postgres 접속 + `factory` role 확인. 실패(P1010 등)면 멈추고 사람에게 role 생성 안내(p1-spec.md S6.0). ⚠️ 슈퍼유저로 role 자가 생성 금지.

**1. 폴더 리셋**: 대상 = `apps/w02-voice-call/`. 있으면 삭제 후 재생성(**정확히 이 경로만** — 상위·타 앱 폴더 금지). 깨끗한 빈 폴더에서 시작.

**2. 1부 — W1 재현**: `docs/p1-spec.md`의 S6(부트스트랩)·S2~S4를 **이 폴더 안에서 그대로 수행**한다. 단 앱 슬러그는 `w02-voice-call` → DB 이름 `w02_voice_call`(하이픈→언더바), `DATABASE_URL`도 그에 맞춘다. 스캐폴드·Prisma 핀·`.env` 생성·`migrate dev`·`db seed`(필립)까지. **여기서 p1-spec.md S5 검증을 먼저 통과**시킨 뒤 2부로 넘어간다(1부가 깨지면 2부 진입 금지).

**3. 2부 — 음성 통화 얹기**:
   - **custom Node server**로 전환(http + `ws`). `dev`/`start`가 이 서버를 타도록. Next 요청은 Next 핸들러로, `/ws`(또는 지정 경로) 업그레이드는 ws 핸들러로 라우팅.
   - **통화 화면 + 진입점**: 채팅방에 "전화 걸기" 버튼 → 통화 화면 라우트. 브라우저 mic 캡처(MediaRecorder)·클라 VAD·오디오 스트리밍 재생.
   - **서버 릴레이 파이프라인**: ws로 받은 발화 오디오 → STT(`/audio/transcriptions`) → LLM(Responses, 통화 instructions) → TTS(`/audio/speech`, mp3 스트리밍) → ws로 오디오 반환. 턴 히스토리는 연결별 세션 메모리.
   - **첫 턴 assistant**: 연결 직후 사용자 입력 없이 아티스트 선턴("여보세요") TTS 재생.

**4. 검증**: S5 실행.

⚠️ **원샷 함정(조사·설계에서)**:
- Next.js App Router + WebSocket = **custom server 필수**(Route Handler로는 ws 못 엶). `dev` 스크립트가 custom server를 타는지 확인.
- **TTS 스트리밍 재생**: mp3 청크를 도착 순서로 재생하려면 오디오 버퍼링(MediaSource/AudioContext) 처리 필요 — 통짜 재생보다 까다로움. 첫 소리 지연·끊김을 실측으로 확인.
- **VAD 자작**: 침묵 임계·길이를 잘못 잡으면 말 끊김/무한 대기. 상수로 빼서 조정 가능하게.
- STT는 **발화 단위 파일 전사**(실시간 ws 전사 아님) — 발화 경계를 클라 VAD가 만들어 서버로 보내는 구조임을 혼동 말 것.
- 오디오 포맷 불일치(WebM/Opus 입력) — `/audio/transcriptions`가 받는 포맷인지 확인.

## S5. 검증 명령

AI가 one-shot 안에서 스스로 실행해 통과를 확인한다.

- **(1부)** p1-spec.md S5 전부: `typecheck` / `lint` / `build` / `prisma validate` / `migrate dev` / `db seed` 통과.
- **(2부)** `npm run typecheck` / `npm run lint` / `npm run build` — 2부 추가 코드 포함 통과.
- custom server 기동 확인: `npm run dev`(또는 지정 스크립트)로 서버가 뜨고 ws 엔드포인트가 업그레이드 응답을 준다.
- (수동 확인용) 통화 1왕복 — 사람 몫으로 Acceptance에 둠(음성 자연스러움은 실측).

## Acceptance Criteria (필수)

완료 선언 직후 사람이 체크한다. **1부(재현)와 2부(격차)를 분리 채점**한다 — Y축 측정은 2부가 대상, 1부는 회귀 통과 여부.

**1부 — W1 재현 (회귀):**
- [ ] `apps/w02-voice-call/`에서 W1 채팅 앱이 그대로 뜬다(가입·리스트·채팅 스트리밍). p1-spec.md Acceptance 통과.

**2부 — 음성 통화 (이번 격차):**
- [ ] 채팅방에서 "전화 걸기"로 통화 화면에 진입한다.
- [ ] 연결되면 아티스트(필립)가 **먼저** "여보세요/hello"를 **음성으로** 말한다(사용자 입력 없이 선턴).
- [ ] 말하면 침묵 감지(VAD)로 발화가 끝나고, 잠시 후 아티스트 답이 **음성으로** 돌아온다(STT→LLM→TTS 왕복 성립).
- [ ] 응답 오디오가 **스트리밍 재생**된다(첫 소리가 통짜 대기 없이 이르게 나옴).
- [ ] mic 권한을 거부하면 명확한 안내가 뜨고 빈 통화로 진입하지 않는다.
- [ ] STT가 빈 결과면 아티스트가 지어내지 않고 다시 듣는 중으로 돌아간다.
- [ ] "끊기"로 통화가 종료되고 채팅방으로 돌아온다. 통화 내용은 **DB에 저장되지 않는다**(휘발).
- [ ] 통화 중 새로고침·네트워크 끊김에서 500 없이 종료/재연결 안내로 처리된다.
- [ ] 페르소나(필립) 톤이 통화에서도 유지되고, 짧게 끊어 말한다(긴 독백 없음).
- [ ] (실측) 턴제(VAD 침묵감지)가 통화로 **충분히 자연스러운지** — run1 교훈대로 사람이 체감 확인.

## Out of Scope

- **립싱크·영상**(W3), 서버 아바타 렌더(W3)
- **진짜 양방향 barge-in**(사용자가 아티스트 말 중간에 끊고 들어가기) — W2.5/W3
